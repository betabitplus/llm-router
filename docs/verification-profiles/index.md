# Verification profiles

Verification profiles define **how** accepted Requirements and Technical requirements are verified.
They are not product requirements and they do not define implementation behavior. A profile selects
verification criteria, Test level, Boundary, Representation, fault applicability, and blocking
project checks by referencing the authoritative contracts and the reusable {doc}`Test plan <../test-plan>`.

Start from the normative Requirement first, then open its profile only when you need verification design.
