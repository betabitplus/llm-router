# 056 — Делегат решает ниже Goal/Feature, ожидание повторов в требовании, битые ответы адаптеров

**Период:** 2026-10-01
**Источник:** сессия Claude Code `8b8b7335-93fe-4a32-bc00-a9e75a4428e8`

## Решения пользователя

- «почему эти вопросы ко мне? Я же беру вопросы только уровня goal и feat … по мелочам не беспокой». Со всеми рекомендациями согласен.

## Что было не так

- Правило «ниже Goal/Feature решает делегат» жило только в заметках агента. В конвейере вердикт `escalate` и пин, который ни одна ступень не написала, ждали «человека» на любом уровне. Агент переслал их пользователю, а вместе с ними и свои инженерные находки.
- Из пяти «эскалаций» три оказались устаревшими: тех мутантов больше нет среди выживших. Действовали только две, обе про отсутствующую фразу технического требования.

## Что сделано

- **Делегат.** Решение ниже Goal/Feature принимает делегат (модель агента, Claude Opus 5.5) и записывает его от своего имени (`by: delegate …`) с причиной; для пина — с путём, по которому может пройти тест. Сборщик больше не перезаписывает автора решения на «person». Это вошло в ADR_0006 и Test Plan; человек может переопределить любое решение.

- **Ожидание между повторами.** TREQ_PROVIDER_RETRY_BOUNDS, ревизия 2: ожидание перед повтором не превышает настроенного максимума. Параметр задаётся в конфиге и проверяется при загрузке, так что намерение очевидно.

  - В профиле новый критерий `VC_PROVIDER_RETRY_WAIT_BOUND` с путями sync/async и два BDD-сценария: ожидания записываются через подменённый `time.sleep`/`asyncio.sleep` и сравниваются с максимумом.
  - Разметка ревизии обновлена в требовании, `@impl`, тегах сценариев и тесте assurance. Старые пины сняты `--revise-pins`.

- **Ждущие пины, решения делегата:**

  - 3 мутанта лимита раундов нерелевантны: публичный ответ на лимите берёт вызовы прямо из ответа провайдера, а не из внутреннего состояния;
  - мутант `c7d2…` — пин: он достижим через `query(..., max_tool_rounds=0)`, при котором инструмент не должен выполниться;
  - мутант байтов — пин: `query(b"abc")` даёт TypeError с упоминанием bytes ещё до запроса; это проверено на коде, первая подсказка оказалась неверной.

- **Адаптеры.** Успешный ответ без сообщения (OpenAI-совместимый, QwenChat) или без текста (Gemini WebAPI) теперь даёт неповторяемую ProviderError, как уже требовали технические требования границ. Три отрицательных контроля `interface.payload-schema` засчитываются и адаптерам, и REQ_PROVIDER_ADAPTER_INTEROPERABILITY.

- **Usage.** total — не меньше input + output, как требует TREQ_USAGE_NORMALIZATION.

- **Скорость пинов.** Черновик, который на оригинале идёт дольше 3 с по времени сессии pytest (медиана пяти прогонов), отклоняется. Восемь медленных пинов оставлены.

- **Порядок стадий.** Стадии читают требования из собранного портала (`needs.json`), а `--revise-pins` — из источника.

  - Первый прогон написал два пина по старой ревизии, и портал перестал собираться.
  - `current_needs` теперь останавливает стадию, пока ревизии портала и источника расходятся.
  - Порядок после правки требования: `--revise-pins` → тесты → портал → квалификация → модели.

- **Решения только о выживших.** Подавляющее решение переносит в «эквивалентные» только выживших; дубликаты и пойманные не трогает (так и проверял гейт).

- **Ещё два решения делегата.** Две цели, ждавшие человека после всех ступеней, тоже нерелевантны: защита от байтов публичным путём не задевается, а ветку `_parse_pydantic_model` со словарём роутер не вызывает: он валидирует текст ответа.

- Два пина по таймауту маршрута падали только в полном прогоне: hypothesis-примеры делят роутер и сервер, а след маршрутов зависит от времени. Пины сняты через `--reject-pin`, мутанты получили новые пины.
