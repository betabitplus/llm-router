# 054 — Аудит практики мутационного тестирования: этапы A–D в глубину

**Период:** 2026-09-30 — 2026-10-01
**Источник:** сессия Claude Code `8b8b7335-93fe-4a32-bc00-a9e75a4428e8`
**План:** [`mutation-testing-practice-audit.md`](../../mutation-testing-practice-audit.md)

## Решения пользователя

- «делай A, потом B и C по порядку и так далее … проверь что бы все запланированное было сделано и реально соответствовало ожиданиям».
- «ВООБЩЕ НИЧЕГО НЕ ПОВТОРЯТЬ. только то что реально новое»; всё, что можно, — параллельно; кэш с актуальными данными не отбрасывать из-за побайтовых сравнений.
- «делаем все в глубину сначала и только после этого рассмотрим вопрос ширины»: этап E (ширина) отложен.
- Коммит — точка фиксации перед побочной задачей в отдельной ветке. Гейт на ней красный по одной проверке (ниже); исправление делается следующим шагом «правильно, а не костылями», и пересчитывать при этом можно только то, что действительно изменится.

## Что сделано

- **A — движок и разметка.** Закрыты пробелы движка E1–E7:
  - замены границ считаются и для `impl.boundary`;
  - добавлены операторы `identity` и `slice`;
  - учитываются мутанты, сработавшие при импорте;
  - аннотации не мутируются;
  - запись в глобальные переменные считается эффектом;
  - аргументы логирующих хуков не мутируются.
  - Кроме того: `@impl` T1–T5, N/A в профилях с обоснованием, объявленные runtime/interface-вызовы и новые сценарии.
- **Отрицательные контроли.** Из 14 runtime/interface-классов, которые не проверял ни один тест, 10 теперь проверяются:
  - обход слоя;
  - медиа `interface.payload-schema` через VCR-реплей: тело запроса снимается отпечатком, а изображение сравнивается по пикселям;
  - `unexpected-interaction` у адаптеров.
  - Остались 4, все `interface.payload-schema` у адаптеров и совместимости.
- **B — пины без приватного.** Пин не читает, не подменяет, не импортирует и не передаёт приватные имена проекта.
  - Сюда входят приватный keyword и приватная опция, которую код проекта пишет строкой, например `_executor`.
  - Пин требования (REQ) не импортирует приватные модули (`llm_router._internal`, `_api`) и не достаёт их атрибутом или строкой с точками.
  - Процессные модули нельзя достать как атрибут модуля вне проекта (`typing.sys`). Клиент модуля проекта остаётся доступен: тест адаптера подменяет транспорт именно там.
  - Модели-авторы нашли три обхода первой версии правила: `llm_router._internal…` атрибутом, `typing.sys.modules[...]` и `**{"_executor": …}`. Эти 11 пинов переписаны через публичный API (локальный сервер из тестовой поддержки, VCR), ни один не потерян.
- **C — поглощение пинов.** `--subsume-pins` строит матрицу «пин × мутант» и выбирает жадное покрытие; `--verify` только проверяет и возвращает нужное.
  - Удалённый пин лежит рядом с записью как `.py.txt`.
  - Возврат применяет текущие правила: копию, которая их нарушает, он не возвращает.
- **D1 — пересмотр.** Вердикт pin, для которого ни одна ступень лестницы черновиков не написала тест, спрашивается снова с вызовами проекта в поле зрения.
  - Лестница считается только после последнего сохранённого пина: пин, снятый позже правилом, её больше не блокирует.
  - Так пересмотрены 3 мутанта: 1 стал эквивалентным, 2 ждут человека.
- **D2 — выборочная перепроверка.** Когда у роли меняется модель или уровень, перепроверяется каждое десятое подавление. Нашлось одно расхождение, оно стало пином.
- **`--reject-pin`** снимает пин, который падает в полном прогоне (зависит от порядка тестов). Его черновик записан в `suite-rejected.json`, и сохранённые ответы его не возвращают.
- **Гейт и страницы.** Класс с нерешённым мутантом страница честно показывает UNKNOWN. Гейт теперь ждёт того же трёхзначного состояния, а в обозревателе у такого пункта есть причина `pending`.
- **agm.** `switch --target agy` возвращает управление раньше, чем меняется хранилище agy; адаптер ждёт подтверждения через `agm sync`.

## Открытая проблема на этом коммите

**Гейт красный по одной проверке:** ансамбль ассессоров не квалифицирован (квалификация 21/22).

- **Что произошло.** Пинов стало больше, а с ними и наблюдаемых пар калибровки.
  - Gemini 3.1 Pro назвал «эквивалентными» 12 из 118 мутантов, различимость которых доказал пин. Это 10,2% при допустимых 10%.
  - Второго семейства моделей, кроме Claude, нет, поэтому ансамбль выключился.
- **Причина — наш вопрос, а не Gemini.** В вопросе поведение обычной функции — это «что вернула и тип исключения».
  - Состояние аргументов после вызова не учитывается, хотя символьный поиск CrossHair `diffbehavior` его учитывает. Не учитывает его и проверка найденного входа (`_observe`).
  - Окружение (переменные, файлы, кодировка) функции входом не считается.
  - В двух из трёх новых «ошибок» Pro ответил строго по нашему определению.
- **Риск.** Все 24 выживших с меткой «вероятно эквивалентен» потом подавлены вердиктом (12 equivalent, 12 irrelevant). У пяти из них есть изменяемые аргументы, часть читает окружение.
- **Состояние шагов.** После переписки пинов перезапущены тесты (525 прошли), кампания и семантика. Триаж, решения, проверка поглощения, архитектура, портал и гейт — ещё нет: их результат зависит от исправления.

**Правильное исправление, следующий шаг:**

1. Поведение — как у CrossHair: результат, исключение и состояние изменяемых аргументов после вызова.
   - Вопрос и проверка входа меняются только там, где аргумент может измениться.
   - Замороженные dataclass, enum и неизменяемые типы вопрос не меняют.
2. Цель, которая читает окружение (переменные, файлы, кодировку, часы), триаж не судит, как уже не судит async и генераторы. Такой мутант идёт прямо к модели вердиктов.
3. Ответ на размеченную пару калибровки привязывается к его точному вопросу, как у наблюдаемых пар. Тогда заново спрашиваются только изменившиеся вопросы:
   - около 6 из 28 размеченных пар;
   - около 46 из 149 наблюдаемых (пары с окружением выпадают);
   - около 11 вопросов триажа;
   - вердикты, у которых изменилась сводка триажа, — до ~40.
   - Всего около 300 вызовов, из них Claude около 150.
4. Порядок: код → квалификация → калибровка → квалификация → триаж → решения → проверка поглощения → портал → гейт.

## Замечено при пуше

- Хук pre-push гоняет тесты в случайном порядке и без `--block-network`. Пин `REQ_CREDENTIAL_RESOLUTION` `adb0de8f41da4f7e` ждал, что запрос к провайдеру упадёт, а это верно только при заблокированной сети.
  - Без блокировки оригинал дошёл до настоящего Gemini web API и прошёл, поэтому пин упал. Он снят через `--reject-pin`.
  - Каскад судит черновики только с заблокированной сетью и такую зависимость не видит. Правило «пин не зависит от блокировки сети» — в следующий шаг.

## Отвергнутые подходы

- **Ослабить порог Test Plan или считать один мутант двух контрактов одним случаем,** чтобы Gemini прошёл: это подгонка проверки под результат.
- **Убрать из калибровки пары, различимые только побочным эффектом:** это спрятало бы слепое пятно вопроса.
- **Поменять текст вопроса через параметр шаблона, не меняя хэш шаблона:** старые ответы засчитались бы на новые вопросы.
- **Добавить новое правило доступа в текст вопроса автору черновиков:** это обнулило бы сохранённые черновики пяти ждущих пинов (около 20 платных вызовов). Автора учит причина отказа.
- **Запретить `adapter.httpx`:** тест границы адаптера подменяет транспорт именно там. Запрещён только процессный модуль, достанутый через модуль вне проекта.
- **Считать кусок f-строки `_API_KEY_` приватной опцией:** кусок f-строки ничего не называет.
