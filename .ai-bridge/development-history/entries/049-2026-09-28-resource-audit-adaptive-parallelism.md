## Что исправлено

- **Отпечатки файлов запоминаются** по пути, размеру и времени изменения (`implementation_faults._remembered`). Пересборка портала заняла 46 с вместо 6,5 минуты. Гейт и квалификация тоже больше не разбирают одни и те же файлы сотни раз.
- **Квалификация по входам.** Три тяжёлые группы (движок, семантический каскад, символьный поиск) читаются обратно, когда не менялись их код в скрипте, их инструменты по смыслу, `uv.lock` и Python (`test-results/qualification-controls.json`). Повторная квалификация — 8 с вместо 225.
- **Решения каскада по черновикам** хранятся по черновику, мутанту, тестам, нормализатору, коду каскада и проекту по смыслу (`test-results/pin-draft-judgements.json`).
- **Пробы** `REQ_INVALID_CONFIGURATION_ERRORS` перезапускаются только при смене их привязки, `--full` запускает их принудительно.
- **Независимые вопросы асессорам задаются пачкой** (`ask_assessors_at_once`): калибровка, выжившие контракта, семантические выжившие.
- **Адаптивная параллельность**, как окно TCP.
  - Предел считается отдельно для каждого пула квоты: аккаунт Claude, пул Gemini, малый пул Antigravity.
  - Медленный старт: предел удваивается, пока все вызовы на пределе отвечены.
  - Ответ о перегрузке делит предел пополам один раз на всплеск (эпохи), дальше рост по одному.
  - Потолок задаёт строка «Parallel calls at most» (8), старт — «Parallel calls to start with» (2).
- **Автор черновиков получает справку о типах** — ту же, что асессоры: поля dataclass и члены enum типов, которые принимает функция.
- **CI.**
  - Общая группа concurrency для push и pull request одной ветки.
  - Результаты мутантов хранятся по входам контракта между прогонами (actions/cache v6.1.0).
  - Токен приватных зависимостей сужен до четырёх нужных репозиториев.
- **Бюджет окон** — 100% по решению пользователя.

## Почему автор черновиков выдумывал API

Вопросы пользователя (утро 2026-09-28):

- почему модели выдумывали API и не могли написать тест;
- есть ли у моделей всё нужное и есть ли слой защиты от такой проблемы;
- как проверить саму проверку;
- как увидеть проблему на сайте;
- может ли модель ссылаться на источники, чтобы было видно, что она не выдумывает.

**Причина — в вопросе, а не в модели.**

- Автор работает без инструментов (так задумано ради изоляции), значит, всё, что человек посмотрел бы сам, должно быть в вопросе.
- Примером служил самый короткий тест контракта, а не тест, который идёт по пути мутанта.
- Ни одна справка не говорила, какие члены у enum и какие аргументы у конструкторов.
- Для внутренней функции правила противоречили друг другу: справка о типах описывала параметры функции, которую пин импортировать не может.

**Сколько это стоило.** Проверка имён прошла по всем 266 сохранённым черновикам. Из 196 непринятых 66 используют то, чего в проекте нет. Чаще всего это `Model.QWEN_MAX` (17 раз), `Provider.OPENAI` и `Model.QWENCHAT` (по 7), `RouterProfile(name=...)`, `ToolCall(arguments=...)` вместо `args` и выдуманный `ProviderUnavailableError`.

## Что сделано

**Вопрос, как у ACH.**

- Пример — тест, который выполняет строку мутанта. Если такого нет, берётся тест, который выполняет его функцию, сначала из тестов контракта (по контекстам coverage.py). К тесту добавлены помощники, фикстуры и константы его модуля: так ACH даёт автору весь тестовый класс.
- Если строку не выполняет ни один тест, второй пример показывает, как проект до неё доходит. Это тест, который выполняет больше всего редких строк функции. Вес строки обратен числу тестов, которые её выполняют: так в выборку попадают пути отказов и переключений маршрута.
- Карточка API говорит, где живёт и как строится каждое имя из примеров, из фокуса вердикта и из описания дефекта. В ней все члены enum и что возвращает каждый метод, на два шага вглубь. Например, `aquery` возвращает `LLMRouterResponse` с полем `routing_trace: list[RoutingAttempt]`.
- Для внутренней функции вопрос прямо говорит идти через публичный API.

**Ссылки на источники и проверка имён (grounding).**

- Ответ обязан перечислить в `sources` все имена проекта, которыми пользуется тест, и взять каждое из примеров или карточки.
- До запуска детерминированная проверка по AST ищет каждое имя в дереве исходников. Так De-Hallucinator привязывает код модели к API проекта.
- Имя, которого модуль не связывает, отсутствующий член enum или чужой аргумент конструктора отклоняют черновик. Причина называет, что есть на самом деле, например: «Model has no member QWEN_MAX; its members are …».
- Если вопрос не решается по одному дереву, это никогда не ошибка. Так бывает с именем из внешнего пакета, ленивым модулем, наследуемым или переименованным конструктором.
- Имена, которые черновик использовал, а вопрос не показывал, записываются как «дыры в контексте». Так видно, полон ли сам вопрос.

**Проверка проверки.**

- Сначала проверку имён прогнали на заведомо правильном коде: на 70 принятых черновиках, 72 пинах и 49 модулях тестов проекта. В 24 модулях она сработала ложно: не учитывала реэкспорт из `py_lib_testkit`, константы модулей и подмодули.
- После исправления ложных срабатываний 0. Все четыре настоящие выдумки дня пойманы с точными сообщениями.
- Теперь это контроль квалификации каскада, в духе квалификации инструментов ISO 26262 и DO-330. На маленьком проекте с известными ответами проверка должна найти ровно выдуманный член, два чужих аргумента, неверный импорт и несуществующий модуль, и ничего — в правильном черновике.
- Гейт каждый раз прогоняет её по всем тестам и пинам проекта. Все они зелёные, поэтому любое срабатывание там — ложная тревога.

**Видимость.**

- Каждая попытка черновика записывается рядом с вердиктами контракта (`drafts.json`). В записи есть вызов, модель, дайджест вопроса, причина, найденное проверкой имён, дыры в контексте и `sources`.
- Причины: принят, не разбирается, выдуманный API, неверное использование API (ошибка на оригинале), неверное поведение, не ловит мутанта, вне правил пина, lint.
- Новая страница портала «Model roles» показывает:
  - здоровье автора черновиков;
  - причины по моделям одной полосой;
  - последние отклонённые черновики;
  - дыры в контексте;
  - канарейки для текущих вопросов;
  - калибровку асессоров;
  - вызовы и цену по ролям из журнала.
- Автор помечается failing, когда принят меньше чем каждый пятый из последних двадцати записанных черновиков (судим от десяти). У TestGen-LLM все фильтры проходит около четверти тестов.
- Страница собирается только из сохранённых записей. Гейт пересчитывает её числа по `drafts.json` и сверяет канарейки с их записями.
- Ссылки на неё есть на главной, в оглавлении и в отчёте о мутантах.
- Старые черновики (до записи попыток) читаются из сохранённых ответов. Принятые определяются по пинам, остальные — только проверкой имён, без запуска.

## Решения пользователя (вечер 2026-09-28)

Пользователь перечитал статус и план и решил по каждому пункту:

- **Движок мутаций** остаётся pytest-gremlins: «функциональность важнее». Он молодой: первый выпуск в январе 2026, статус Alpha, 53 звезды. mutmut зрелее (с 2016 года, 1,5 тыс. звёзд), но не размечает мутантов по классам отказов, на которых стоит ADR_0003.
- **Ответы моделей на сайте** — доделать: вопрос и ответ каждой роли, а не только генератора.
- **Источники** — «перестраховка нужна на всех уровнях»: каждая модель, где это имеет смысл, ссылается на то, на чём стоит её ответ.
- **griffe** — попробовать и брать, только если он что-то решает лучше. Лишних зависимостей не тянуть.
- **Размеченный набор задач** для автора черновиков пока не нужен: хватает оценки по записанным попыткам.
- **Застрявший пин.** Писать тест самому — «как будто хак». Вместо этого лестница:
  - без инструментов, если так делают крупные компании;
  - затем с инструментами;
  - затем модель верификатора с пометкой, чтобы следующая версия верификатора могла её перепроверить.
- **pyright, ty и другие детерминированные инструменты** — разобраться, чем они помогут моделям и сэкономят ли переделки.
- **Вызовы Opus 5.5** не откладывать: лимит большой.

## Источники на всех уровнях

- **Асессоры.**
  - Код в вопросе стоит в блоках, текста требования больше нет: эквивалентность от него не зависит (пункт «Не забыть» из утра).
  - Ответ цитирует строки кода, на которых стоит вердикт.
  - Детерминированная проверка находит каждую цитату в вопросе дословно (пробелы не в счёт) и требует, чтобы хотя бы одна задевала изменённую строку.
  - Ответ, который не проходит проверку, не считается, и асессора спрашивают снова.
- **Вердикт и ревью.**
  - Цитаты из слов требования, фичи, цели или критерия, на которых стоит вердикт, и хотя бы одна изменённая строка.
  - При нарушении вопрос задаётся ещё раз с тем, что сломалось. Гейт восстанавливает исходный вопрос и пересчитывает источники и проблемы.
- **Генератор мутантов** источники не цитирует. Всё, что он утверждает, проверяется исполнением, а относимость мутанта к требованию решает вердикт с источниками.
- **Автор черновиков** цитировал и раньше: `sources` и проверка имён.
- **Проверка проверки.** Контроль квалификации гоняет её на маленькой функции, у которой ```` ``` ```` стоит внутри строки кода, и сравнивает с точными ожидаемыми сообщениями. Новый контроль канареек: верный вердикт с чужой цитатой проваливается.

### Проверка проверки поймала регресс вопроса асессорам

- **Что поймали.** После первой калибровки с источниками ансамбль асессоров не прошёл квалификацию. Gemini 3.1 Pro назвал эквивалентными 6 из 57 заведомо различимых пар при пороге 10%. Со старым вопросом таких пар был 1.
  - На трёх давно известных парах его ответ сменился с «различимы» или «не уверен» на «эквивалентно».
  - Причина везде ложная: «у `LLMRouterConfig` нет атрибута `models` (или `default_max_tool_rounds`), значит обе версии падают одинаково».
- **Почему.** Справка о типах в вопросе показывала только поля dataclass, без свойств. Раньше модель спасал текст требования: по нему было видно, что код работает. Урок тот же, что утром у автора черновиков: модели не хватало контекста.
- **Что исправлено.**
  - Справка перечисляет и свойства с типами, которые они возвращают.
  - Вопрос прямо говорит, что обе версии выполняются в проходящих тестах проекта, поэтому всё, что читает код, существует.
  - Просьба о цитатах больше не подталкивает к «эквивалентно».
  - В контроль квалификации добавлен класс со свойством.
- **Цена.** Ещё один переспрос калибровки.

## Лестница и помощь автору черновиков

- **Без инструментов сначала — так и делают.** В Agentless (FSE 2025) конвейер без агента решил больше и дешевле любого агента того времени на SWE-bench Lite. У Meta (ACH, TestGen-LLM) конвейеры тоже без инструментов. Инструменты — ступень для того, что конвейер не решил: так CoverUp даёт модели функцию `get_info`.

- **Подсказки без модели**, по данным. Из 13 попыток, записанных после исправлений утра:

  - 4 приняты;
  - 4 не ловят мутанта;
  - 4 неверно ведут себя на оригинале;
  - 1 неверно использует API.

  Поэтому подсказки целятся в «не ловит» и «не доходит»:

  - **условия пути к изменённой строке** из кода функции: ветки, циклы, обработчики, ранние выходы (path constraints SymPrompt, FSE 2024). Для `62fc1b`: «строка 560 выполняется, только если `isinstance(exc, LLMRouterError)` ложно»;
  - **покрытие слабого черновика на мутанте** (coverage feedback CoverUp, FSE 2025): не дошёл до изменённых строк, дошёл до части или прошёл их все, ничего не проверив. Оператор считается по первой строке, заголовок функции — не вызов.

- **Ступени с инструментами.**

  - Ступень 2 — Sonnet 5, ступень 3 — модель верификатора (Opus 5.5).
  - Каждая работает в копии проекта: код, тесты и настройки, без истории и без домашней папки.
  - Разрешено: читать и искать по копии, писать один файл будущего пина, запускать одну команду — проверку каскада. Проверка показывает правила, пять прогонов на оригинале, прогон на мутанте, покрытие и находки pyright как совет.
  - Работает только через CLI Claude: его разрешения держат инструменты внутри копии. У agy инструменты не отключаются.
  - Каскад судит итоговый ответ заново. Пин третьей ступени помечен в заголовке и на странице.

- **Живая проба границ** одним вызовом Haiku ($0.03):

  - чтение внутри копии, запись разрешённого файла и разрешённая команда прошли;
  - чтение вне копии, чтение из домашней папки, другой файл и `ls ~` отклонены;
  - ничего не просочилось.

- **Бюджет:** новая строка «List price per call with tools» — $5.00.

- **pyright и ty — не фильтр.** Замер на 279 сохранённых черновиках и копии 125 модулей тестов проекта:

  - с настройками проекта они ловят 85 из 89 находок проверки имён и ещё 35;
  - на правильных тестах ложно срабатывают в 4% (pyright) и 2% (ty) модулей, с проверкой атрибутов — в 10%;
  - выдуманные члены enum при настройках проекта не видят.

  pyright остался советом в проверке ступени с инструментами.

- **griffe не взят.** Как основа проверки имён он из коробки ложно сработал на 45 из 125 модулей тестов, наша проверка — на 0.

## Отвергнуто

- **Мутанты только на строках последнего пуша, а не всей ветки.** Находки должны относиться ко всему изменению, как на ревью у Google. Кэш по входам делает полный diff дешёвым.
- **Кэш по входам для всех 20 производителей квалификации.** Остальные 17 вместе идут 8 секунд, а риск ошибиться во входах того не стоит.
- **Кэш тестов и портала в CI.** Они дают покрытие и граф для diff и с кэшем uv идут около полутора минут.
- **Повторы вызова с экспоненциальной задержкой при перегрузке.** Сейчас перегруженный вызов идёт к следующей модели роли, а оставшийся без ответа вопрос подхватывает следующий прогон.
- **Тест человека для `62fc1b`.** Пользователь назвал его хаком. Вместо этого лестница, и она мутанта поймала.
- **Инструменты для каждого черновика.** Конвейер с полным вопросом решает большую часть дешевле (Agentless), инструменты — ступень для остального.
- **pyright и ty как фильтр черновиков.** Они ложно срабатывают на правильных тестах проекта, а выдуманных членов enum при его настройках не видят.
- **griffe как основа проверки имён.** 45 ложных срабатываний из 125 против 0.
- **Цитаты у генератора мутантов.** Всё, что он утверждает, проверяет исполнение.
- **Откатить вопрос асессорам после провала порога.** Причина была в неполной справке (не было свойств), а не в цитатах.

## Не забыть

- **Когда сбросится недельный малый пул** (около 17:50 4 октября): `--calibrate-assessors` для Opus 4.6.
- **В вопросе асессорам нет тел функций из других модулей**, которые вызывает цель. Gemini Pro счёл безвредным удалённый вызов `validate_config(config)` (пара `a2e61f`). Нужна карточка вызываемых функций (сигнатура, docstring, какие исключения бросает), как у автора черновиков.
- **«Дыры в контексте»** считают и имена, которые модель с инструментами нашла, читая код. Считать только первую ступень или показывать по ступеням.
- **Пайплайн работает через второй вход CLI Claude.** Вернуть `model_generation.py profile default`, когда у первого сбросится неделя.
- **Цена вызова с инструментами** ($5.00) — пересмотреть по журналу. Первые вызовы стоили от $0.09 до $1.71.
- **Вернуть процентные пределы окон**, когда пайплайн начнёт мешать собственной работе в той же подписке.
- **Потолок параллельности** (8 на пул) пересмотреть по журналу: `parallel_limit`, `in_flight`, `backed_off`.
- **`ternforge-infra-ci`:** кэш результатов diff и сужение токена — забрать в переиспользуемый workflow, заодно проверить токены в `python-library.yml`.
- **`py-testkit`:**
  - адаптивный предел на пул, пакетные вопросы асессорам, справка о типах со свойствами;
  - запоминание отпечатков, кэш решений каскада, кэш тяжёлых групп квалификации;
  - проверка имён черновика с её контролем, запись попыток с причинами;
  - второй пример для невыполняемой строки, карточка API по возвращаемым типам;
  - условия пути, покрытие слабого черновика;
  - проверка цитат у вердикта, ревью и асессоров;
  - вызовы с инструментами в копии проекта, лестница и её проверка.
- **`ternforge-docops`:** страница Model roles, опубликованные вопросы и ответы, ссылки на них из explorer.
- **Проверка имён читает только дерево проекта.** Имена из внешних пакетов (`py_lib_testkit`) она считает существующими, и их ошибки видны только при запуске черновика.
- **Порог здоровья автора** (каждый пятый из двадцати) пересмотреть по собственным записям пилота, когда их наберётся хотя бы 50.
