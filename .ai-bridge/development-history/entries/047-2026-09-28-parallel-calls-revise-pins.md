# 047 — Параллельные вызовы моделей и смена ревизии одной командой

**Период:** 2026-09-28
**Источник:** сессия Claude Code `da8ca61e-4ead-4f90-81b4-cfc36a37e733`

## Решения пользователя

После коммита 046 пользователь попросил идти по отложенным шагам повторного аудита. По параллельности: «2 одновременно точно можно». Больше ставить только в пределах официальных лимитов Antigravity и с запасом. Предел по возможности подбирать умно, а если стратегии не видно, хотя бы писать в журнал всё, что нужно для решения потом.

## Что выяснилось

- **Лимиты Antigravity.**
  - Официальная страница планов: квота Google AI Pro «refreshed every five hours until weekly limit reached», расход считается по объёму работы агента.
  - Ограничений на одновременные запросы там нет. Расход виден в настройках приложения, у CLI такой команды нет.
  - В сообществе описан недельный потолок сверх пятичасового.
  - По нашему журналу пул Gemini за двое суток не отказал ни разу. Второй пул (Claude 4.6) отказывает на пятичасовых окнах, недельной блокировки не было.
- **Покрывающие тесты на мутанта движок уже выбирает сам.** pytest-gremlins запускает на мутанта только тесты, покрывающие его строку. Этот фильтр включён по умолчанию, и мы его не выключаем. Пункт из 046 был ошибкой повторного аудита: я судил по числу тестов в плане контракта, а не по тому, что движок запускает.
- **«Застрявшие» мутанты — это бюджет, а не дефект.**
  - На один вопрос даются две оплаченные попытки черновика, как у Meta конечное число кандидатов.
  - Когда попытки исчерпаны, следующий прогон бесплатно проигрывает сохранённые ответы и новых не просит.
  - Поднять число попыток — решение о квоте.
- **Упакованные ссылки git ломают локальную сборку портала.**
  - После коммита 046 git сам упаковал ссылки (`git gc --auto`).
  - sphinx-codelinks 1.4.0 ищет коммит ветки только в отдельном файле `.git/refs/heads/<ветка>` и в `packed-refs` не смотрит. Его предупреждение `[codelinks.git_ref]` сборка считает ошибкой.
  - Помог файл ветки с тем же коммитом, а следующий коммит пишет его сам. В CI свежий checkout: там файл ветки есть или HEAD отсоединён.

## Что сделано

- **Параллельные вызовы.**
  - Независимые вопросы задаются одновременно (`Run.call_many`): асессоры одного выжившего, вердикты и ревью пачки выживших, черновики одного раунда.
  - Бронирование вызова, окна квоты и журнал меняются под одной блокировкой, поэтому лимит прогона не переполняется.
  - Каждый бэкенд ведёт не больше «Parallel calls per backend» из Test Plan, сейчас 2.
  - Ответ о перегрузке делит предел бэкенда пополам до конца прогона: 503 без мощности, 429 или rate limit. Сам предел не растёт.
  - Каждая строка журнала вызовов пишет, сколько вызовов её бэкенд вёл одновременно и при каком пределе. Это данные для решения о повышении.
  - Вердикты сохраняются пачками, поэтому прерванный прогон не теряет оплаченных ответов.
- **`--revise-pins`.**
  - Смена ревизии требования делается одной командой, без ручного разбора, как в 046.
  - Команда снимает пины, проверяющие старую ревизию, вместе с записями. Ревизия берётся из исходников документов, потому что с такими пинами портал не собирается.
  - Калибровка пересобирается из сохранённых ответов, без вызовов.
  - Следующее решение задаёт новый вопрос и пинит мутант заново.
- **Квалификация** проверяет:
  - предел параллельности;
  - лимит прогона при одновременном бронировании;
  - порядок результатов;
  - отступление при перегрузке и запись об этом в журнал.

## Итог

- Квалификация 20/20. Тесты: 277 passed. Портал собран, специализированные пробы 4/4, гейт PASS.
- Ни одна модель не спрошена, поэтому кампания и вердикты остались актуальными: 309 мутантов, 120 записей вердиктов, 50 пинов.

## Не забыть

- Поднимать предел выше 2 — по журналу вызовов: `in_flight`, `parallel_limit`, `seconds`, `backed_off` на реальных прогонах.
- **`py-testkit`:** `Run.call_many`, предел на бэкенд и его отступление, `--revise-pins`.
- **`ternforge-docops`:** сборка портала должна узнавать коммит ветки через git, а не из файла ссылки, иначе после `git gc` локальная сборка падает. Исправление самого sphinx-codelinks (`get_current_rev`) — upstream.
