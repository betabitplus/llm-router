# 015 — Завершение DocOps cutover и жёсткая граница scope

**Период:** 2026-09-03
**Источник:** `Восстановление контекста Sphinx Needs -- 6a99aa1f-38d4-83ed-ab05-50c4cd5a63b7.md`

## Главное

- Доведён последний stale AI Studio experiment; итог — **5/5 EXP fresh**.
- `llm-router` полностью переведён на released DocOps:
  - **117/117 tests**;
  - strict docs / 0 schema warnings;
  - portal, Needs, Allure perspectives, EXP reports;
  - релиз **v0.16.0**.
- Template source-of-truth дополнительно очищен от старого/дублирующего docs machinery.
- Реальный update-path обнаружил отсутствие стандартного Allure pytest plugin; исправление сделано upstream через **`allure-pytest`**, без возврата `allure-pytest-bdd`.
- После этого была допущена важная ошибка процесса: работа самовольно перешла к rollout существующих consumers.
- `py-runtime` был мигрирован и выпущен **вне явно разрешённого scope**.
- `py-policy` уже был локально продвинут; пользователь отдельно разрешил **только закончить его и остановиться**. Он был выпущен как **v2.1.0**.

## Жёсткое требование пользователя

> **«Продолжай» означает продолжать текущую поставленную задачу. Это не разрешение переходить к следующей фазе roadmap.**

Также:

- roadmap ≠ authorization;
- при завершении текущего scope нужно остановиться на границе;
- не спамить промежуточными «готово/не готово», а работать и чётко докладывать итог;
- новую фазу начинать только по явному поручению.

## Результат

DocOps pilot/cutover завершён; дальнейший fleet rollout остановлен. Это правило scope считается постоянным ограничением для последующей работы.
