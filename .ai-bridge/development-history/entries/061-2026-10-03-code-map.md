# 061 — Этап 2: связь код → требование и Карта кода

**Период:** 2026-10-03
**Источник:** сессия Claude Code `8b8b7335-93fe-4a32-bc00-a9e75a4428e8`

## Решения пользователя

- «доброе утро, продолжай»: по плану — этап 2 (пункты 4, 6, 7, 14, 16, 37).
- Форма Карты кода — из демо: «A + B как вид «Таблица»». Основной вид — карта-плитки, как Health Map; список модулей — второй вид «Table», как таблица Health Map.

## Зачем

- Метки `@impl` до сих пор служили только кампании мутаций, которая сужает их до строк. Со стороны кода не было видно ничего: какие функции не служат ни одному требованию, какие функции требования его тесты не исполняют, каким кодом ничто не пользуется и почему строки не исполняются.
- DO-178C (6.4.4.3) относит каждую строку, которую не исполнили тесты требований, ровно к одной причине: нет теста, нет требования, лишний код, код отключён намеренно. BMW LOBSTER трассирует каждую функцию к требованию или записывает, почему требование не нужно.

## Что сделано

- **ADR_0008: владение кодом — по функциям.**

  - Функция служит требованиям, чья метка `@impl` стоит на ней или внутри неё: для владения метка охватывает всю функцию, кампания мутаций по-прежнему берёт только её строки. Метка на классе охватывает его методы, метка на регистрации — функции, которые та называет.
  - Функция без метки служит требованиям вызывающих её функций (помощник наследует владельцев) — по статическому графу вызовов: имена, импорты, псевдонимы модулей, `self`/`cls`, атрибуты, в которых класс держит экземпляры. Что вызывается только динамически, остаётся ничьим.
  - Ничья функция — провал, если делегат не записал причину (`.ai-bridge/code-exemptions.json`, пока продукт не меняем).
  - Метка утверждает, что функция реализует каждое названное требование, поэтому её обязаны исполнить тесты каждого из них; помощник подтверждён, если его исполняет тест любого его требования. Тест считается за требование, если проверяет его или выведенное из него.
  - Неиспользуемый код находит vulture; то, что пакет отдаёт наружу, используется вызывающими. Класс, которым ничто не пользуется, — отдельная метка на карте.
  - Каждая неисполняемая строка получает одну причину. Недостижимые строки считаются лишними, хотя coverage.py их вообще не видит.
  - Числа, которые могут только уменьшаться: ничьи, неподтверждённые исполнением, неиспользуемые, строки по каждой причине. Базовая линия (`.ai-bridge/code-map-baseline.json`) опускается сама. Рост без записанной причины валит гейт; с причиной новое число становится базовым, а рост с причиной остаётся в истории `accepted`.

- **Карта кода (`code-map.html`) — на родном движке Health Map.**

  - Общий движок карты научился называть свои метки (`MAP_TERMS`): у Health Map — цели, возможности и контракты, у Карты кода — области, модули и функции. Всё остальное общее: лента слоёв с FAIL/PASS, вид на открытой карточке (Map | Table), таблица всех слоёв, фильтры, поиск, ссылка, Changes, адрес, клавиши, тёмная тема, телефон.
  - Четыре слоя: Owner (кому служит), Run by its tests (исполняют ли тесты её требования), Used (пользуется ли ею что-то), Unexecuted lines (почему строки не исполняются). Плитка тем больше, чем больше в функции строк.
  - Карточка функции: кому служит и как, где стоит каждая метка и что она охватывает, сколько тестов её исполняют и сколько из них — тесты её требований, какие строки не исполняются и почему.
  - Таблица: каждая функция со значением каждого слоя, ссылками на требования, тестами и причинами; группировка по области и модулю, по Owner, по требованию; CSV.
  - Фильтр «Serves» по требованию: страница требования ведёт на карту, где горят только его функции.
  - В панели фильтров каждого слоя — числа, которые могут только уменьшаться.

- **Страница требования — раздел «Code».** Функции, которые служат требованию (по метке и как помощники), сколько из них подтверждено исполнением, по каждой — тесты требования, все тесты, причины неисполняемых строк, ссылки на карту и на исходник. Общий статус контракта раздел не меняет: это сведения, а не новый слой вердикта.

- **Квалификация `PRODUCER_CODE_MAP`.** Маленький пакет, где у каждой функции известный ответ: функция с меткой, её помощник с недостижимым кодом, функция с меткой двух требований, которую исполняют тесты только одного, исключение с причиной, регистрация, неиспользуемая функция и класс, экспортируемый класс, ничья функция с неисполненной веткой, ветка `# pragma: no cover`, подпакет с абсолютным импортом. Настоящие pytest и coverage.py. Контроль ловит все 12 нарочно посаженных ошибок карты, в том числе ошибку затенения имени, найденную в 061 до контроля, и рост храповика, принятый без причины.

- **Гейт:** факты пересчитываются; у каждой функции состояние и значения слоёв по правилам; строка — одна причина внутри своей функции; храповик держится; исключения действительны; производитель квалифицирован; карта рисует каждую функцию один раз; 58 требований связаны с картой в обе стороны; Карта кода в навигации. Проверка храповика: посаженный рост (базовая линия 6 неиспользуемых при 7 настоящих) уронил гейт «rose without a recorded reason», с записанной причиной гейт прошёл; базовая линия восстановлена.

- **Баги монитора, найденные по ходу (исправлены):**

  - coverage.py не видит недостижимый код после `return`: строки `aistudio._native_part` 280–281 пропадали из счёта. Теперь их находит vulture, и они считаются лишними;
  - три класса ошибок, которые никто не бросает, не попадали на карту: у них нет функций. Теперь класс, которым ничто не пользуется, — отдельная метка;
  - страница требования сначала считала помощника неподтверждённым, если его исполняли тесты только другого его требования, а карта — подтверждённым. Теперь обе считают по одному правилу ADR_0008;
  - длинный путь функции в таблице налезал на соседний столбец; «1 lines» в двух местах.

## Итог прогона

- Карта: 449 функций и 3 класса. Owner — 61 ничьих (88 по метке, 303 помощника, 0 исключений). Run — 46 не подтверждены исполнением. Used — 7 неиспользуемых. Строки без теста — 299, без требования — 72, лишние — 6, отключённые намеренно — 0.
- У REQ_ROUTE_TIMEOUT_FALLBACK 17 функций: одна по метке, 16 помощников; 16 подтверждены исполнением, `_normalize_tool_choice` — нет.
- Гейт PASS: 8486 проверок. Квалификация 23/23. Тесты, кампания и модели не перезапускались: карта читает сохранённый прогон.

## Открыто

- Все четыре слоя красные — это правда о продукте: публичный фасад и склейка без меток, функции требований, которые его тесты не исполняют, неиспользуемые классы ошибок, недостижимый код в `aistudio._native_part`. Продукт не меняем, требования не добавляем — числа держит храповик.
- Исключений пока нет: ни одна ничья функция не оказалась кодом, которому требование не нужно.
- Раздел «Code» не меняет общий статус требования: у REQ_ROUTE_TIMEOUT_FALLBACK вердикт PASS, а раздел FAIL. Сделать ли код слоем вердикта (и Health Map) — открытый вопрос монитора.
- Раздел Test Plan о Карте кода отложен: Test Plan — вход свежести доказательств, его правка требует перезапуска тестов. Правила записаны в ADR_0008.
- Карта показывает функции из сохранённого прогона coverage: функция, добавленная после прогона, появится после следующего прогона тестов (до него штамп показывает устаревшие доказательства).
