# 050 — Ширина мутационного тестирования, явные уровни рассуждения, семантические мутанты для всех требований и скорость

**Период:** 2026-09-28 (ночь) — 2026-09-30
**Источник:** сессия Claude Code `da8ca61e-4ead-4f90-81b4-cfc36a37e733` и её продолжение

## Решения пользователя

- **План расширения.** Берутся все пункты плана 1–7, шестой тоже. Потолок цены вызова ($5 с инструментами) остаётся, но не должен стать искусственным ограничением: цены моделей меняются, а помнить о потолке никто не будет.
- **Лимит вызовов.** Лимит на прогон поднят с 40 до 200 («медленно»). Общий расход он не меняет, только число перезапусков.
- **Уровни рассуждения.**
  - Уровень каждой модели задаётся явно. Sonnet 5 заменяется на Sonnet 5.5 во всех ролях.
  - Начинать с минимального уровня и повышать, только если модель не справляется.
  - Канарейки нужны только до первого уровня, который их прошёл: «если минимальный проходит, то и дальше пройдёт».
- **Вердикт.**
  - Вердикт окончательный, лестницы у него нет. Opus 5.5 на `xhigh`, потому что первые вердикты фактически шли на `xhigh`: «раз было xhigh, то его и оставляй, нечего менять по сто раз».
  - Fable 5.1 не берётся («не понравилась»).
  - Давать ли судье инструменты, пользователь доверил решить мне.
- **Баланс квот (временный).** Сначала модели подписки Claude. Gemini — там, где нужна другая семья моделей (ревью вердикта, второй и третий асессоры), и как запасной. Потом порядок вернут обратно.
- **Каналы и аккаунты.**
  - Обе подписки работают одновременно.
  - Аккаунты внутри подписки переключаются автоматически, без участия человека.
  - Пользователь завёл второй и третий аккаунты Antigravity. Лимиты больше не главное: ускорить всё, что можно.
- **Лестница автора черновиков.** Оставить только уровни с действительно значительной разницей. Каждый мутант поднимается по лестнице сам, не дожидаясь остальных.
- **Отложено.** Непривязанный к требованиям код («потом сделаем»).
- **Аудит скорости после 050** принят целиком: «нужно все делать и исправлять, все принимается».

## Ширина мутационного тестирования (план 1–7)

- **Потолки цен.**
  - Потолок роли — значение из Test Plan или трижды самый дорогой отвеченный вызов этой роли, что больше. Когда цены растут, потолок растёт сам.
  - Вызов, упёршийся в потолок, получает свой исход `capped`. Его спрашивают ещё раз с двойным потолком, потом у следующей модели роли, и мутант поднимается по лестнице.
  - Страница Model roles показывает потолки и остановленные вызовы, гейт пересчитывает это по журналу вызовов.
- **Восемь операторов Python.** Шесть из PyTation, `conditional` из Stryker и PIT, `negation` — унарная вставка Google. Шум отсекается:
  - обязательный аргумент функции проекта не удаляется;
  - `while` не превращается в «→ True»;
  - вызов-инструкция и `await` не укорачиваются;
  - атрибут меняется только на похожий хотя бы наполовину;
  - дубли удаления инструкции не строятся.
- **Общий код.** Строку, на которую претендуют несколько требований, проверяет каждое требование своими тестами. Слишком широкие `@impl` сужены по формулировкам требований. В `src/` менялись только комментарии `@impl`.
- **Архитектурные мутанты.** Для каждого из 9 правил import-linter вставляется запрещённый импорт. Правило ловит свою вставку, и нарушается ровно оно.
- **Мутанты исхода сценариев.** Меняется ожидаемое значение в коде шага Then или его помощника: 180 мутантов. Детектор «шаг ничего не сверяет» прослеживает проверки через вызовы помощников.
- **Карточка вызываемых функций.** В вопросе асессорам есть сигнатура, первая строка docstring и исключения каждой функции проекта, которую вызывает цель.
- **Вердикт ждёт полного суждения.** Вердикт «неясного» выжившего ждёт, пока ответят все места асессоров. Раньше его спрашивали при неполном суждении и переспрашивали позже, тратя Opus и Gemini дважды.
- **Прогон мутаций.** 53 требования вместо 28, 1095 мутантов вместо 277. Без `@impl` осталось 5 требований.
- **Находка.** 78% строк функций `src/` (3843 из 4906, 381 функция) не входят ни в одну область `@impl`. Это отложено.

## Уровни рассуждения

- **Находка.** `--safe-mode` не отключает уровень, сохранённый в настройках входа CLI.

  - В основном входе был сохранён `xhigh` для Opus 5.5: на нём шли первые 135 вердиктов.
  - Профиль пилота настроек не имеет, поэтому 331 вердикт после них шёл на умолчании Claude Code для Opus 5.5, `medium`.
  - Канарейки вердикта прошли на обоих уровнях, все вердикты остаются.
  - Теперь каждый вызов передаёт `--effort` и `--setting-sources ""`, а каждая строка журнала записывает уровень.

- **Лестница уровней.** Повышается только роль, каждый ответ которой проверяет запуск: автор черновиков, его ступень с инструментами и последнее средство. Судьи и генератор отвечают на одном уровне: калиброванный порог держится только для измеренного уровня.

- **Канарейки.** Уровни лестницы проходят канарейки снизу, до первого прошедшего. Уровни выше отвечают без канареек, а их ответы всё равно проверяет запуск.

- **Меньше уровней (по решению пользователя, по данным).** Сколько пинов сохранила каждая ступень в эпоху Sonnet 5.5:

  | Ступень                       | Уровень  | Сохранено |
  | ----------------------------- | -------- | --------- |
  | Автор черновиков              | `low`    | 73 из 110 |
  | Повтор автора                 | `medium` | 33 из 64  |
  | Автор с инструментами         | `medium` | 24 из 32  |
  | Автор с инструментами         | `high`   | 5 из 8    |
  | Последнее средство (Opus 5.5) | `high`   | 0 из 3    |
  | Последнее средство (Opus 5.5) | `xhigh`  | 1 из 3    |

  Новая лестница: автор `low` → `high` (повтор через ступень), с инструментами только `medium`, последнее средство только `xhigh`. У застрявшего мутанта 4 шага вместо 6.

- **Лестницу первого асессора** (поиск уровня по порогам калибровки) не трогал: выше `low` она не используется, а смена таблицы асессоров пересобирает калибровку.

## Калибровка асессоров

- **Находка.** Новые пины доказали различимость многих реальных выживших. Gemini 3.8 Flash назвал эквивалентными 16 из 104 различимых пар (15% при допуске 10%). Раньше пороги считались только по опорным парам, и это было занижение.
- **Пороги.** Теперь пороги считаются по всем наблюдённым различимым парам: не меньше 80% подтверждённых входов на опорных парах и не больше допуска ложных «эквивалентен».
- **Выбывание.** Асессор, ни одна модель которого не держит пороги, в новых вопросах не участвует. Его старые ответы остаются в прежних суждениях. Метке «вероятно эквивалентен» нужен откалиброванный набор из двух семей моделей внутри участников, и все участники должны сказать «эквивалентен». Судят Sonnet (5.5 на `low` или 5) и Gemini 3.1 Pro.

## Семантические мутанты для всех требований (P3)

- **Таблицы.** 27 Verification Profiles получили таблицы по правилу: каждый требуемый класс `spec.*` и `interface.*` на каждой функции области `@impl`, бюджет 2. Это 139 пар; мутанты есть у 29 требований.
- **Выборка — класс на цели.** Одна функция теперь стоит в нескольких строках с разными классами, поэтому генератор, каскад и гейт знают выборку как «класс на цели».
- **Результат принадлежит предложению по месту.** Id мутанта — дайджест его нормальной формы, так что один мутант под двумя классами несёт один id дважды (такие повторы есть в 16 требованиях). Слияние кусков каскада, Explorer, вопросы вердиктов, черновики и гейт теперь сопоставляют результат с предложением по позиции. Запись, которая не совпадает с предложениями по местам, не считается актуальной.
- **Каскад.**
  - Тип, который модуль импортирует только для проверки типов, оставляет функцию без стратегии входов. Раньше это роняло каскад.
  - Пределы времени берутся из прогона мутаций: 1,25 × время этих тестов плюс 10 с, подтверждение при вдвое большем.
  - Зависание считается пойманным, как в PIT и Stryker. Тесты мутанта идут в своей группе процессов, и по тайм-ауту убивается вся группа.
  - В калибровку каскада добавлены мутант, который виснет (C-HANGS), и мутант, повторяющий другой (C-REPEATED).

## Аккаунты Antigravity и два канала

- **Аккаунты.** Адаптер читает квоты всех аккаунтов через `agm` и переводит на аккаунт с остатком только CLI (`--target agy`), IDE не трогает. В конце прогона CLI возвращается на прежний аккаунт. В журнале аккаунт назван дайджестом.
- **Моя ошибка.** Отказы «Individual quota reached» я принял сначала за ограничение частоты, потом за общую недельную квоту человека. На деле `agm list` помечал второй аккаунт как аккаунт CLI, а хранилище учётных данных `agy` держало первый, у которого неделя Gemini кончилась. Вызовы шли на первый аккаунт, а записывались на второй. Из-за моего вывода пользователь не стал добавлять новые аккаунты.
- **Исправление.**
  - Какой аккаунт использует `agy`, говорит `agm sync`, а не список.
  - Переключение засчитывается, только когда хранилище держит новый аккаунт.
  - Отказ и время сброса квоты записываются только на подтверждённый аккаунт (`account_verified`). У каждого аккаунта своя недельная квота.
- **Два канала.** Если у первой модели роли заняты все места, отвечает следующая модель роли на другом канале. Вход Claude с полным окном сам переходит на другой профиль машины.

## Скорость

- **Замер.** Из 23–25 минут этапа вердиктов модели занимали 2–3. Остальное время уходило на локальные прогоны тестов.
- **Каскад.**
  - Предложения требования режутся на куски по 3. Мутанты с одинаковой нормальной формой держатся в одном куске, чтобы повтор оставался дубликатом.
  - Куски всех требований идут в 8 процессов сразу, крупные требования первыми.
  - Требование, чьи входы не менялись, не перезапускается.
- **Черновики пинов** проверяются в 8 процессах сразу. Каждый мутант поднимается по лестнице сам, как только отвергнут его собственный черновик.
- **Вызовы моделей.** Параллельных вызовов для начала 8, максимум 16.
- **Итог.** Этап вердиктов — 4 минуты вместо 23, полная цепочка с вызовами моделей — 22 минуты.

## Гейт узнал, что изменил P3

Гейт впервые за 050 дошёл до поздних проверок. Часть его ожиданий оказалась снимком пилота до P3:

- пойманный по тайм-ауту мутант проверка считала непойманным;
- классы семантических мутантов считались без вердиктов, хотя засчитанный вердикт «эквивалентен» или «не относится» выводит выжившего из класса;
- пять проверок требовали, чтобы модели отказов маршрутизации, устойчивости и провайдеров оставались частичными.

Теперь правило одно для всех. Пока хоть один обязательный класс не проверен, модель отказов и итог FAIL. Когда проверены все, модель проходит ровно тогда, когда пойман каждый класс. Полные модели выводятся из фактов, а итог требования учитывает и обязательные Technical requirements.

## Утечка окружения в свидетельство (2026-09-30)

- **Находка перед коммитом.**
  - Символьный поиск подобрал для `REQ_CREDENTIAL_RESOLUTION` имя переменной окружения `PATH`, и функция вернула её настоящее значение с путём домашней папки.
  - Оно попало в вопрос вердикта, в реальную канарейку и в сохранённые ответы.
  - В историю git ничего не попало. Секретов в найденном нет, но так же мог утечь и ключ.
- **Исправление.**
  - Показанный исход (свидетельство оценки выживших и дифференциального прогона) называет переменную окружения без значения (`<$NAME>`) и домашнюю папку без пути. Решение сравнивает полные исходы по дайджесту, а не этот текст.
  - Квалификация проверяет подстановку.
  - Гейт проверяет, что ни один файл, который попадёт в репозиторий, не содержит домашнего пути машины.
  - Вердикт и пин этого мутанта сняты и заданы заново уже чистым вопросом. Текст канарейки очищен, канарейки прогнаны снова, старые ответы с путём удалены.
  - Пин был и доказательством различимости одной наблюдённой пары в калибровке асессоров, поэтому калибровка пересобрана из сохранённых ответов без этой пары, как при `--revise-pins`, без вызовов моделей.
  - Ответ принятого вызова нельзя просто стереть: гейт требует ответ каждого принятого вызова, это след аудита. Поэтому ответ **отзывается**: строка вызова в журнале остаётся, `semantic-mutants/withdrawn-answers.json` называет его с причиной, файл ответа удалён, и гейт проверяет, что ни одна текущая запись на него не ссылается. Правило записано в ADR 0004.

## Канарейка «irrelevant» оказалась пограничной (2026-09-30)

- После правки текста одной канарейки весь набор вердикта задали заново. Opus 5.5 на `xhigh` на реальном случае V-REAL-IRRELEVANT (`REQ_TOOL_CHOICE`) ответил «pin», хотя в 11:06 отвечал «irrelevant». В самом вопросе стоит подсказка суждения «a pin must reach it», и обе оценки защитимы. Пограничный случай не канарейка: он проверяет удачу, а не модель.
- Непройденная канарейка заблокировала уровень вердикта, и снятый вердикт не был задан заново.
- Замена — реальный случай, однозначный по формулировке требования: `TREQ_SESSION_SERIALIZATION` `92622e5a` убирает только отступы в JSON, а требование говорит о байтах медиа и версиях. Opus и ревьюер Gemini оба сказали «irrelevant», вход, на котором версии различаются, подтверждён запуском, и вопрос канарейки побайтно совпадает с вопросом настоящего вердикта.
- Опасную ошибку вердикта (подавить настоящий пробел) по-прежнему ловит канарейка «pin». Gemini Flash как ревьюер провалил её («irrelevant» вместо «pin») и остаётся заблокированным ревьюером. Первым ревьюером работает Gemini Pro.

## Аудит скорости после 050 (2026-09-30)

Сверено с PIT, Stryker, mutmut, Google и возможностями самого pytest-gremlins. Реальные точки роста:

1. Новый пин заставляет заново гнать всех мутантов своего требования (в циклах 240–455 с). PIT, Stryker и сам pytest-gremlins (`--gremlin-cache`) перезапускают только мутантов, которых покрывает новый или изменённый тест. Ключ кэша движка не учитывает общие входы тестов, поэтому наша привязка по требованию остаётся, а кэш сбрасывается при их смене.
2. Внутри требования мутанты идут по одному. Когда переделать надо 1–3 требования, работают 1–3 ядра из 9. У движка есть `--gremlin-workers`.
3. Семантический мутант гоняет все тесты требования до конца: 236 прогонов, около 25 минут процессорного времени. Эталоны запускают только тесты, покрывающие изменённую функцию, и останавливаются на первом упавшем. Покрытие по тестам у нас уже есть. Туда же — кэш результата мутанта по входам, чтобы новые ответы асессоров не гоняли его тесты заново.
4. Оценка выживших пересчитывает все требования с нуля при каждом вызове, по одному: 85–92 с на вызов, даже когда ничего не менялось. Нужно то же, что уже сделано в каскаде: пропуск неизменившихся и параллельный прогон.
5. Мелочь в скрипте цепочки: тесты после последнего цикла гоняются, даже если он не принял ни одного пина (40 с).

Уже на уровне эталонов: в CI мутируются только изменённые строки; для обычных мутантов тесты выбираются по покрытию и запускаются через fork; тайм-ауты — как в PIT; неинтересный код отсекается; неизменившиеся требования не перезапускаются; параллельность вызовов моделей подстраивается сама.

## Мои ошибки и уроки

- Правка основной копии во время цепочки трижды портила прогон:
  - сборщика — запись квалификации устарела, и прогон отказал моделям;
  - `semantic_mutants.py` — результаты каскада устарели;
  - Test Plan после pytest — доказательства устарели.
- В скрипте цепочки `A || B && C` в shell — это `(A || B) && C`.
- Состояние автора пинов по одному отпечатку мутанта: общий мутант двух требований получил чужой пин. Задето 7 из 233 пинов, переписаны штатно.
- Сначала я сказал пользователю, что вердикты шли на `medium`, не проверив настройки входа. На деле первые 135 шли на `xhigh`. Урок: проверять настоящее значение настройки и держать то, что действительно работало.
- Моя ошибка с аккаунтами Antigravity описана выше: я поверил столбцу статуса `agm list`, не сверив его с хранилищем `agy`.
- Слияние кусков по id потеряло строки первых экземпляров повторяющихся мутантов: испорчено 7 записей каскада, после вердиктов. Исправлено, записи пересчитаны.

## Сознательно отвергнуто

- **Мутанты сценариев с подменой шага Then** другим исходом фичи. Подставленный шаг приносит свою проверку и роняет сценарий, даже если исходный шаг ничего не сверял.
- **Инструменты судье вердикта.**
  - У Meta (ACH, arXiv 2501.12862) точность судьи эквивалентности подняла статическая предобработка, а не инструменты. Предобработка у нас есть: символьный поиск, входы с проверкой запуском, асессоры, карточка вызываемых функций.
  - Agent-as-a-Judge (arXiv 2410.10934) выигрывает на пошаговой работе агентов.
  - Вызов с инструментами у нас примерно в 5 раз дороже.
  - Условие на будущее: вердикт «pin», для которого ни одна ступень не написала тест, пересудить с чтением проекта.
- **Fable 5.1 для вердиктов** — по решению пользователя.
- **Канарейки на каждом уровне лестницы** — по решению пользователя.
- **Лестница уровней у судей:** калиброванный порог держится только для измеренного уровня.
- **Правило «Individual quota → все аккаунты»** держалось на моей ошибке и удалено.

## Состояние на момент коммита

- Пользователь завёл пять аккаунтов Antigravity. Третий Antigravity не допускает: «Eligibility check failed … Verify your account». Подтвердить его — действие пользователя в приложении Antigravity.

- Пайплайн переключил `agy` на этот аккаунт, потому что квота у него больше всех. Канарейки ревью Gemini не получили ответа, и две мои ошибки вышли наружу:

  - канарейка без ответа записалась как провал и затёрла прошлый успешный результат;
  - неподтверждённый аккаунт не обходится, как исчерпанный.

- Из-за этого ревью Gemini заблокированы. Вердикт «irrelevant» по мутанту `TREQ_ROUTE_ORDER`, заданный заново, остался без ревью, а подавление без ревью не засчитывается. Поэтому `TREQ_ROUTE_ORDER` и `REQ_ROUTE_STICKY_START` снова красные: итог PASS у 5 страниц вместо 7.

- Ещё одна моя ошибка, найденная перед коммитом: прогон сценарных мутантов пишет снимок входов сохранённого прогона тестов (`evidence-run-inputs.json`) поверх настоящего, потому что не уводит его во временную папку, как каскад и кампания. Гейт это поймал: доказательства тестов потеряли базу свежести. Тесты прогнаны заново; сама ошибка исправляется в 051.

- Хук ty нашёл в скриптах 050 две ошибки типов (словари со значениями разных типов). Исправлены аннотациями, поведение не менялось.

  - 12 неиспользуемых директив `ty: ignore` в плагине операторов (`ternforge_mutation.py`);
