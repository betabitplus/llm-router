# 004 — Удаление старого verification/E2E framework

**Период:** 2026-08-25 → 2026-08-26
**Источник:** `Восстановление контекста Ternforge -- 6a8e1e23-6834-83eb-a29a-c243fdd70d32.md`

## Главное

- После успешного пилота начали убирать платформенные предположения старой E2E-модели.
- Цель — не добавить новый BDD-слой поверх старого, а **удалить старую инфраструктурную обязанность**: hand-written verification pages, E2E slice registry, direct-run conventions и связанные проверки.
- Cleanup прошёл через `py-policy`, templates, `py-runtime`, `py-testkit` и `llm-router`.
- Сохранялись только действительно полезные общие механизмы; всё, что существовало исключительно ради старой verification-модели, становилось кандидатом на удаление.
- **Workbench не считался автоматически мусором**: его роль отделили от старого E2E framework и не удаляли просто по названию.

## Требования пользователя

- Не заменять старый custom framework новым custom framework.
- Не оставлять compatibility-layer без реальной необходимости.
- Чистить источник истины платформы, чтобы старый мусор не возвращался через Copier/template updates.
- Перед удалением общего механизма проверять его фактическую роль, а не делать cleanup по совпадению терминов.

## Результат

Платформенная модель стала заметно проще: BDD/specification начали опираться на стандартные инструменты, а не на историческую E2E taxonomy Ternforge.
