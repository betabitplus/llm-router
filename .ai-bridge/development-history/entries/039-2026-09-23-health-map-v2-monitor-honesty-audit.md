## Health Map v2

- Goal/Capability — нейтральные контейнеры; статусом заливаются только контракты (REQ, TREQ). Собственные проверки Goal/Capability — точка и тонкий красный контур.
- Plotly заменён на вендоренный d3-hierarchy 3.1.2 (SVG, порядок узлов сохраняется).
- Наведение — нейтральное кольцо вместо яркой обводки; смена цвета идёт через нейтральный серый; подсказки короткие и простые.
- Каждый слой отвечает только на свой вопрос: Execution — только то, что реально запускалось; Evidence quality — только удержанные доказательства; результат теста засчитывается один раз, за тот случай, для которого он написан.

## Ревизия инфраструктуры монитора

Требование пользователя: продукт может быть красным, но монитор не должен быть бутафорией — всё, что он показывает, должно реально измеряться.

- `impl.control-flow` был захардкожен как непроверенный, мутации шли только для REQ_INVALID. Теперь классы Implementation считает одна кампания для всех контрактов с `@impl`: зона кода берётся из IMPL needs графа; строка засчитывается контракту, только если остальные её владельцы выведены из него; оракул — собственные прошедшие тесты контракта; класс «пойман», только если пойманы все его мутанты.
- Облегчённый исполнитель pytest-gremlins вызывал тесты без pytest и засчитывал «поимку» любому тесту с фикстурами, параметрами или BDD, который не мог вызвать. Пилот REQ_INVALID показывал 93.5% / 100%, реально — 43.5% / 0%. Теперь каждый мутант гоняется полноценным pytest (локальный плагин), а квалификационный контроль ловит этот режим отказа.
- Зонды перезаписывали снимок входов удержанного прогона — базу свежести. Теперь они пишут в отдельное место, а снимок, снятый не в начале удержанного прогона, даёт свежесть UNKNOWN.
- Уровни M&S вычисляются из графа: L2 только при калибрующем EXP с валидным отчётом капсулы. Цель L0 означает «не требуется», а не PASS.
- Упавший тест, который `verifies` контракт вне обязательных случаев профиля, роняет покрытие контракта.
- Верхний монитор судит продюсеров, реально участвовавших в доказательстве, и уровень, границу и реализм пути.
- Инспектор отказов по каждому классу пишет: пойман, пропущен или не проверен — с причиной и выжившими мутантами.

## Сознательно отклонено

Общие мутаторы для spec/interface/runtime/architecture: в 73 из 80 BDD-сценариев в `Then` нет литералов, а «выключить слой» или «подменить исход» дают почти гарантированный зелёный. Для этих классов остаётся механизм test-plan — тест-вызов с фиксацией инъекции.

## Ускорение мутационной кампании

Пока всё экспериментально живёт в `llm-router` (`.ai-bridge`, MAP-P21):

- мутируются только строки `@impl` контракта; сверка с полным прогоном — 148 из 148 мутантов совпали по id и статусу, время 70 → 15 минут;
- результат контракта переиспользуется, пока не изменились движок, зона кода, тесты или входы; любая правка кода продукта перезапускает все контракты, потому что мутант может увести выполнение в код, который обычный прогон не трогал.
