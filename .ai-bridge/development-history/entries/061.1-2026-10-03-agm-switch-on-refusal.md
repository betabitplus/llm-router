# 061.1 — Аккаунт Antigravity меняется по отказу, квоты не опрашиваются

**Период:** 2026-10-03
**Ветка:** `fix/agm-switch-on-refusal`, отошла после 061 (`12a7d77`) и влита в `experimental-assurance-portal`. Этап 062 в это время лежал в рабочей копии незакоммиченным, поэтому запись боковая: она не трогает общий список и счётчик.
**Источник:** сессия Claude Code `7641718b-9f84-42a2-8449-5bd838f1df39`

## Решение пользователя

- Вопрос: не грозит ли бан из-за `agm`. Проверка по коду форка `agm` показала:
  - модели прогон вызывает только через официальный `agy`; банили за другое — за вызов моделей сторонним клиентом с логином Antigravity;
  - сам `agm` ходит в Google, когда обновляет токен (обычный OAuth, клиент самого Antigravity) и когда читает квоты (`refresh`, `refresh-all`, `watch`, `auto-switch`): это запрос во внутренний API Antigravity от имени `antigravity/1.11.3`;
  - только чтение квот формально попадает под §6 условий Antigravity («сторонние программы обращаются к сервису»). Адаптер делал его в начале каждого прогона, по всем аккаунтам сразу.
- Решение: «да, переделай refresh-all в llm-router на переключение по ошибке… нужно пофиксить, хорошее замечание». Способ — отдельная ветка и слияние — пользователь оставил на выбор.

## Что сделано

- **Квоты не читаются.** `AgmAccounts.snapshot()` больше не вызывает `agm refresh-all` и не берёт проценты из `agm list`: только какие аккаунты есть и какой из них держит хранилище `agy`. Всё это `agm` берёт из своих записей, ничего не спрашивая у Antigravity.
- **Аккаунт меняется по отказу.** `Run.choose_account` держит аккаунт, пока отказ не потратил его квоту для модели, и тогда переводит `agy` на следующий аккаунт по алфавиту алиасов, по кругу от текущего. Остальное как было: вызов повторяется на новом аккаунте, сброс, названный в отказе, помнится между прогонами, недопущенный аккаунт пропускается шесть часов, неподтверждённое переключение — за хранилищем `agy`.
- **Свободная доля квоты.** Строка Test Plan «Antigravity quota kept free» остаётся 0%. Держать долю свободной без чтения квот нельзя, поэтому значение больше нуля откладывает каждый вызов Antigravity с этой причиной, а не молча игнорируется.
- **Журнал вызовов.** Пробный вызов больше не пишет остатки квот, их больше нет.
- **Квалификация.** Проверки адаптера переписаны с процентов на отказы; сценарии те же (поворот и возврат, запомненный сброс, хранилище против списка, недопущенный аккаунт, неподтверждённое переключение). Добавлены две: прогон спрашивает у `agm` только `alias`, `list` и `sync`; доля свободной квоты больше нуля откладывает вызов.
- **Test Plan.** Абзац про аккаунты описывает новое поведение и почему.

## Почему так

- Обращение к внутреннему API — единственное, что в нашей связке похоже на запрещённое; без него `agm` только переключает хранилище `agy` и обновляет токен, как это делает сам `agy`.
- Цена: пустой аккаунт стоит одного отказа, а отказ токенов не тратит. Порядок аккаунтов теперь по алиасам, а не «у кого больше осталось».

## Отклонённые варианты

- **Читать кэш `agm list` без обновления.** Проценты в нём устаревают и вводили бы в заблуждение.
- **Подправить версию в User-Agent `agm`.** Это маскировка обращений, а не отказ от них.
- **Отдельная правка в ветке `experimental-assurance-portal-site`.** Ветка не запускает этапы с моделями и не меняла адаптер с 054; при слиянии обратно она получит исправленную версию без конфликта, а своя копия правки этот конфликт создала бы.
