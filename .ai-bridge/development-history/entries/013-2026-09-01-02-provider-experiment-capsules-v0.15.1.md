# 013 — Provider-level Engineering Experiment capsules

**Период:** 2026-09-01 → 2026-09-02
**Источник:** `Изучи контекст Sphinx Needs -- 6a974233-b568-83ed-acd8-bb3ddb9bea1e.md`

## Главное

- Эксперименты укрупнили до **5 provider-level capsules**, вместо множества узких экспериментов по каждому отдельному кейсу.
- Каждый capsule получил:
  - собственное изолированное окружение;
  - реальный исполняемый код;
  - inputs/assets;
  - capture результатов;
  - causal digest/freshness;
  - отдельный human-readable report.
- В отчётах показывается реальный код эксперимента через `inspect`, а не вручную продублированный пример.
- Медиа и другие артефакты сохраняются рядом с experiment evidence.
- Generic структурные правила isolation/capsule layout вынесены upstream в `py-policy`/templates.
- Sphinx-specific EXP presentation оставлена в пилоте, пока модель не доказана.
- `llm-router` выпущен как **v0.15.1**.

## Требования пользователя

- Эксперимент должен быть реально переносимым и запускаемым отдельно.
- Никаких ручных копий кода в документации.
- Freshness должна отражать причинную зависимость, а не формальный timestamp.
- Не делать слишком мелкие EXP, если один provider-level вопрос логически объединяет несколько проверок.

## Результат

Engineering Experiments превратились из концепта в независимые воспроизводимые evidence-capsules.
