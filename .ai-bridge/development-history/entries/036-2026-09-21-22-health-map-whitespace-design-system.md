# 036 — Health Map: whitespace hierarchy и единый visual system

**Период:** 2026-09-21 → 2026-09-22
**Источник:** `Продолжение работы над Sphinx -- 6ab1b8d4-ce34-83ed-a25f-9444a111c886.md`

## Тяжёлый parent-container отвергнут

Попытка сделать Goal выраженным header/panel ухудшила карту:

- hierarchy всё равно не читалась достаточно быстро;
- тёмные overlays перегружали интерфейс;
- карта потеряла лёгкость.

Принято новое направление:

> **hierarchy различаем прежде всего whitespace, а не тяжёлыми рамками и заливками.**

Карта вернулась к чистому treemap-виду.

## Spacing-based hierarchy

- sibling Goal разделяются заметнее;
- Feature внутри Goal — плотнее, но тоже должны читаться отдельно;
- hover/lineage не должны уничтожать gaps;
- дополнительные decorative frames/keylines убираются.

Labels Goal/Feature сохраняют один читаемый размер; слишком маленькая cell остаётся без текста, а не получает микрошрифт.

## От отдельных цветов к системному visual language

После функциональной стабилизации пользователь отдельно потребовал убрать «пестроту» и сделать карту частью цельного UI.

Первый слишком muted вариант ушёл в грязные/бурые оттенки и был отвергнут.

Зафиксировано:

- PASS остаётся настоящим зелёным;
- FAIL остаётся настоящим красным;
- hierarchy может менять lightness/value, но не semantic hue;
- N/A использует neutral gray;
- surfaces, borders, radii, hover/focus и motion должны быть частью одной tokenized system.

Итоговая концепция:

**neutral system UI + semantic red/green + hierarchy by value/spacing + consistent interaction language**.

## Следующий визуальный gap

Goal separation стал заметнее, но Feature separation всё ещё почти не воспринимался.

Пользователь потребовал существенно увеличить визуальное расстояние между sibling Feature.

Эта итерация вскрыла следующий важный вопрос: **настоящее ли это пространство или просто более толстая рамка?**

## Точка остановки

Следующий источник продолжает именно с проверки механизма Feature gap. Архитектуру/semantics карты менять больше не требовалось — только довести hierarchy geometry.
