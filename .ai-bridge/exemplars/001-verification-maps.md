# Эталон 001 — Verification Maps

**Что это:** три страницы на одном runtime:

- `verification-health-map.html` — судит;
- `verification-depth-map.html` — измеряет;
- `verification-map.html` — прототип, где слой — вопрос, а ответ — его здоровье и меры.

**Где живёт:**

- `.ai-bridge/assurance_map_pages.py`: общий runtime `MAP_SHARED_JS` / `MAP_SHARED_CSS`, описания страниц `HEALTH_*`, `DEPTH_*`, `PAIRS_*`;
- гейт `validate-mutation-pilot.py`;
- реестры MAP-P19–P40 и DEPTH-P34–P48;
- журнал 039–043.

**Период и статус:** 2026-09-23 — 2026-09-26. Принятая точка: пользователь сказал «в целом мне теперь всё нравится».

## 0. Почему это эталон

1. **Смысл раньше вида.** У каждой части страницы есть вопрос, на который она отвечает. Всё, что не отвечает на вопрос, убрано.

2. **Одна система, а не набор экранов.** Три страницы работают на одном runtime. Страница только описывает свои слои, различия между страницами — только смысловые.

3. **Сквозные инварианты сильнее локальных удобств:**

   - «ничего не прыгает»;
   - «статус и иерархия — разные визуальные каналы»;
   - «выбранное нейтрально»;
   - «монитор честен».

   Каждое решение проверялось на соответствие им.

4. **Каждое решение закрывает названную боль.** У каждого есть запись в реестре (что, почему, доказательство, владелец, откат) и проверка в гейте.

5. **Путь проходился итерациями.** Варианты показывались демо-страницами на настоящих данных, на переломах изучались референсы. Если решение читалось как баг, его быстро откатывали.

## 1. Смысл: вопросы страницы

| Часть                                        | Вопрос (дословно на странице)                                                             | Что показывает                                                                                                         |
| -------------------------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Overall · Health                             | Where does each contract fail?                                                            | Круг: вердикт в центре, кольца целей, способностей и контрактов, по кольцу на слой; луч — один контракт через все слои |
| Overall · Depth                              | How deep do its own tests go?                                                             | Лучи через кольца уровней тестов, цвет — граница                                                                       |
| Overall · Table                              | Health and measures per contract                                                          | Кольца Overall, развёрнутые в строки                                                                                   |
| Execution                                    | Did its tests and scenarios pass?                                                         | Treemap вердиктов                                                                                                      |
| Coverage · Health / Test level / Boundary    | Is every required case tested? / How far do its tests reach? / What do its tests talk to? | Одна и та же карта в трёх цветовых кодировках                                                                          |
| Fault model · Health / Mutants caught        | Are its required faults caught? / How many planted bugs are caught?                       | То же                                                                                                                  |
| Evidence quality · Health / Model validation | Is its evidence sound and fresh? / How well are its substitutes checked?                  | То же                                                                                                                  |
| Assurance                                    | Do goals and capabilities pass?                                                           | Собственные проверки целей и способностей                                                                              |

Принципы смысла:

- **Health судит, Depth измеряет** (042). Красный и зелёный только там, где страница судит. Меры показаны последовательными шкалами, «не измерено» — штриховкой. Это единственное неустранимое различие двух карт.

- **Монитор не бутафория** (039). Продукт может быть красным, а монитор — нет:

  - всё, что он показывает, реально измеряется;
  - тест засчитывается один раз, за тот случай, для которого написан;
  - у «не измерено» есть причина;
  - ложный зелёный запрещён.

  Пример: пилот REQ_INVALID показывал 93.5% пойманных мутантов, а после замены исполнителя на полный pytest — 43.5%.

- **Вопрос вида открывает легенду:** «Is every required case tested? ■ Fail 7 ■ Pass 68 …». Человек сначала читает вопрос, потом ответ.

- **Красное объясняет себя** (041). 61 одинаковая красная плитка Fault model оказалась пятью разными работами: причины стоят в панели и в карточке при наведении.

## 2. Информационная архитектура: порядок чтения

Сверху вниз, от обзора к уликам (progressive disclosure: `overview → selected signal → drill-down → forensic`):

1. **Заголовок и строка прогона:** какой удержанный прогон, сколько проверок, коммит, свежи ли доказательства. Когда стоят фильтры, на её месте чипы и «N of 63 contracts».
2. **Лента слоёв** — карточки с вердиктом, счётом, мини-картой и точками видов:
   - Overall первой и закреплена;
   - дальше Failing · N по убыванию провалов, линия «ок», Passing · N в исходном порядке;
   - на краях ленты счёт спрятанных красных и зелёных слоёв;
   - «All layers» раскрывает таблицу всех слоёв (040: лента C + скрытая таблица E).
3. **Открытая карточка → её виды.** Слайдер миниатюр выезжает из карточки, на которую человек уже смотрит (043).
4. **Легенда в одну строку:** вопрос, цвета со счётом, «+N», «?».
5. **Карта и боковая панель Filters.** Панель сдвигает вид, а не перекрывает его. Сверху Kind, под разделителем — фильтры вида.
6. **Карточка при наведении:** плашка, путь, строки, «Opens …» словами целевой страницы → страница Contract evidence.

Решения по расположению:

- **Одно место — один сигнал.** В строке легенды только легенда. Счёт контрактов живёт у чипов. Причины провалов переехали из строки под лентой в панель.
- **Kind — постоянное место с разделителем.** Путь был такой: подвал каждой панели → строка инструментов (перегрузила её) → у заголовка → верх панели Filters. Kind задаёт выборку для всех видов, поэтому стоит первым и одинаково везде.
- **Виды на карточке, а не в отдельной строке.** Ряд вкладок, вкладки перед легендой, дорожка, слайдер — блок не притягивал взгляд, как его ни выделяли. Решение — перенести его туда, куда человек уже смотрит.
- **Таблица — полноценное второе представление Overall, а не урезанная выжимка:**
  - колонки идут в порядке ленты, у каждой группа с суммами;
  - шапка по пути колонки;
  - шапка и имя контракта остаются на виду при прокрутке.

## 3. Модель взаимодействия

- **Адрес вида:** `#вид:ID?фильтры`. «Назад» со страницы контракта, присланная ссылка и Copy link возвращают тот же слой, вид, контракт и фильтры.
- **Фильтры:**
  - внутри фасета OR, между фасетами AND;
  - наведение на опцию подсвечивает её контракты, клик оставляет только их;
  - панель показывает только уместные виду фасеты;
  - пустая опция выключена, а не спрятана;
  - Kind — фасет-переключатель (один kind или все), выбранный kind становится чипом.
- **Виды слоя:**
  - радиогруппа: стрелки ходят по кругу, Home и End — к краям, одна остановка Tab;
  - бегунок можно тянуть;
  - слой помнит свой вид, и миниатюра карточки показывает вид, в котором слой откроется;
  - у закрытой карточки точки видов.
- **Прогрессивное раскрытие видов** (043):
  - при трёх видах и больше карточка открывается на полтора вида с «› +N»; «+N» или выбор вида дальше первого раскрывают все, и они остаются раскрытыми;
  - повторный клик по карточке сворачивает виды, следующий открывает;
  - другая карточка начинает заново;
  - **Overall всегда раскрыт целиком**: он особенный, и его виды — разные представления, а не перекраска.
- **Пустой вид** (043) не прячется, а бледнеет, и подсказка объясняет: «Nothing to show under the filters: all 6 contracts they keep are “Not measured”». Выбрать его можно, в панели видны причины.
- **Клавиши:**
  - F — панель;
  - `/` — Find (самое проблемное первым);
  - T — таблица;
  - V — следующий вид;
  - 1–9 — слой;
  - стрелки — карточки и виды;
  - Esc — закрыть.
- **Changes** (041): карточки показывают новые провалы и исправления с прошлого удержанного прогона, а кнопка обводит их на карте. Пока снимок один, кнопка честно выключена.

## 4. Инвариант «ничего не прыгает» и приёмы

Боль, которую называл пользователь:

- скачет строка легенды на `#overall/depth`;
- скачет карта при открытии панели и при Rings/Table;
- карточка уезжает из-под курсора;
- слайдер дрожит на 2 px.

Правило: **любой клик сохраняет положение и размер каждого блока.** Проверяется пробами на 1280, 820 и 375 px.

| Приём                                         | Где применён                                                                                                    | Пример                                                                |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Резервировать место, а не добавлять и убирать | Rings/Table прятался, но не удалялся (MAP-P28); строка видов на узкой странице есть всегда, даже при одном виде | Высота строки 60 px от слоя к слою                                    |
| Одна строка, остальное за «+N»                | Легенда                                                                                                         | Overall › Depth: «+3» открывает Missing, Mutants caught, Not measured |
| Раскладка один раз на ширину страницы         | Treemap: панель только сужает плитки, кольца только сдвигаются                                                  | Ни один контракт не переезжает                                        |
| Фиксированные рамки                           | Все виды одной высоты; карточки 78 px; рамка миниатюры 54 × 30                                                  | Три вида = три одинаковых сегмента                                    |
| Резерв ширины жирного начертания              | Имя вида: `::after{content:attr(data-name);font-weight:750;height:0}`                                           | Выбор вида больше не меняет ширину слайдера                           |
| Анимация к точной ширине                      | Слайдер: `max-width = трек + паддинг + рамка` вместо запаса 520 px                                              | Складывание стартует сразу, с той же скоростью, что раскрытие         |
| Рисовать один раз, менять только числа        | Плитки Kind, чипы                                                                                               | Иконки не мигают при подгрузке                                        |
| Докрутить один раз, когда геометрия устоялась | Лента: после раскрытия и складывания, со свежей шириной закреплённого Overall, по заново найденной карточке     | Нет двойных прокруток и отката за Overall                             |
| Держать отступ от органов управления          | Открытая карточка стоит в 80 px от краёв ленты (кнопки прокрутки 72 px)                                         | «+2» не встаёт рядом с «✖1 ›»                                         |

**Урок — последовательность важнее хитрости.** Трюк вкладок Chrome («не менять ширину, пока курсор на ленте») убрал сдвиг карточки на 235 px. Но слайдер складывался то сразу, то нет, и пользователь принял это за баг. Трюк откатили (MAP-P37), а сдвиг смягчили одинаковой скоростью складывания.

## 5. Визуальный язык

- **Статус и иерархия — разные каналы** (036–039). Иерархия передаётся геометрией, пробелами и скруглениями; статус — цветом, и только у контрактов. У целей и способностей статус — точка и тонкая обводка своей проверки. Толстые рамки как «зазор», тяжёлые шапки групп и микрошрифт отвергнуты.
- **Выбранное нейтрально** (MAP-P19): акцентный цвет сайта на карте не используется, гейт это проверяет.
  - выбранная карточка приподнята, с рамкой цвета текста;
  - наведение — нейтральное кольцо вместо синей обводки, которая «слишком хорошо» привлекала внимание;
  - цвет меняется через нейтральный серый.
- **Слайдер приглашает переключить:**
  - утопленная дорожка и приподнятый бегунок, как в segmented controls;
  - скруглены только внешние концы, средние сегменты прямоугольные;
  - форма бегунка следует месту: first, middle, last;
  - свечение под выбранным убрано.
- **Одни знаки везде.** Глифы kind одинаковы в панели, карточке, таблице и Find. «?» — одно короткое простое предложение, пояснения прячутся за «?» и не крадут место.
- **Редкий провал заметен, но не кричит** (MAP-P40):
  - от красной точки расходится кольцо (2.6 с), обводка переходит от красного к янтарю (3.2 с);
  - это работает только если провалов немного (≤3 или ≤¼ оценённых);
  - зелёное неподвижно; в светлой теме янтарь темнее.
- **Обе темы и reduced motion** везде: вместо анимации статичный ореол.
- **Пространство имён классов.**
  - `tf-map-*` — общее, `tf-health-*`, `tf-depth-*`, `tf-pairs-*` — страниц; стили страниц скоупятся `#verification-health-map` / `#verification-depth-map`.
  - Два реальных урока:
    - кнопки слайдера с классом карты `tf-map-view` отдали SVG карты свои отступы и рамку;
    - класс `table` у миниатюры унаследовал от темы `margin-bottom:1rem`, и слайдер стал на 4 px выше карточки.

## 6. Движение

- **Движение объясняет изменение, а не украшает:**
  - новая легенда проявляется вместе со своим видом;
  - бегунок скользит к выбору;
  - панель сдвигает вид кадр за кадром;
  - слайдер раскрывается и складывается за одно время.
- **Анимировать исключения, а не норму.** Пользователь одобрил отдельно: где проваливается многое, красного и так много, и мигание стало бы навязчивым.
- **Превью при наведении отвергнуто** (MAP-P40). Все виды, кроме Overall, — одна карта в других цветах, превью не даёт якоря для запоминания. Превью уместны только там, где они в тему.
- **Статичное состояние самодостаточно.** Анимация только усиливает то, что уже видно без неё.

## 7. Адаптивность

- **До 640 px** виды открытого слоя стоят строкой во всю ширину под лентой: 440 px карточки со слайдером не помещались в 343 px, и лента уводила карточку из виду. Повторный тап там ничего не сворачивает.
- **До 960 px** панель встаёт над видом.
- **375 px:** горизонтальной прокрутки страницы нет. Перетаскивание бегунка работает пальцем (`touch-action: pan-y` только у выбранного сегмента), в остальном лента прокручивается как обычно.
- **Слишком широкая карточка со слайдером** показывает своё начало: карточка никогда не уходит из виду ради своих видов.

## 8. Доступность

- Лента — `tablist`/`tab` с `aria-selected` и одной остановкой Tab; карточка с видами несёт `aria-expanded`.
- Виды — `radiogroup`/`radio` с `aria-checked`; стрелки, Home и End по APG.
- Пустой вид сообщает причину через `aria-description`, скрытая подсказка карточки называет её виды.
- Декор (бегунок, точки, свотчи) — `aria-hidden`.
- У каждого действия мышью есть клавишный эквивалент: перетаскивание ↔ стрелки, наведение на опцию ↔ фокус и клик.

## 9. Архитектура: одна карта, страница — описание

- **`mapPage` владеет всем общим:**

  - виды, адрес, фокус и клавиши;
  - карточка при наведении, контур, дуга и родители;
  - фильтры, Changes, лента, таблица, Find;
  - раскладка и старт.

  Общие модули: `mapTree`, `mapTiles`, `mapRings` (одно ядро колец `RING_CORE`), `mapFilters`, `mapKinds`, `mapTable`, `mapFrame`, `mapStrip`.

- **Страница — описание:** `layers`, `views`, `says`, `describe`, `tone`, `blank`, `legend`, `facets`, `panels`, `strip.card/row/cells`, `table`, `tiles`, `rings`, `find`. Объём это подтверждает:

  - общий runtime ≈ 158 КБ;
  - Health ≈ 28 КБ, Depth ≈ 42 КБ;
  - Verification Map ≈ 11 КБ: он собирает фабрики `healthMap` и `depthMap` в `pairsMap`.

- **Правило минимального неустранимого различия** (042, требование пользователя): страницы сближаются даже ценой правок Health Map. Остаётся только то, что сломает смысл, если убрать: группы Failing/Passing против Measured, красный и зелёный против шкал, матрица Layer × health против Test level × boundary.

- **Факты и вид разделены** (041). Билдер — адаптер фактов в JSON (`rows`, продукт первым, только читаемые поля). Разметка вынесена из отпечатка квалификации, поэтому правка вида не делает производителей UNKNOWN.

- **Правила «пусто» и «цвет» — на странице.** `blank(row, projection)` и `tone(...)` задаёт каждая страница, и общий код не знает, что «none» у границы означает Local, а у мутантов — «не измерено».

## 10. Процесс: как принимались решения

1. **Живая страница, а не описание.** Пользователь смотрит на локальный портал и называет боль словами: «скачет», «незаметно», «перегружено», «то сразу, то не сразу».
2. **Варианты на демо-страницах на настоящих данных**, когда направление неясно: лента против More и панели (040), варианты Depth Map, приёмы акцента, мини-страницы, виды в карточке (A–E → E). Демо не удаляются, пока пользователь не разрешит.
3. **Референсы на переломах.** Не «как принято», а конкретный переносимый приём с указанием, откуда он (раздел 11).
4. **Выбранное строится на исходных компонентах.** «Чисто исходные табы бери и механику варианта E».
5. **Измерять, а не предполагать:**
   - пробы положения и размера каждого блока на 1280, 820 и 375 px;
   - обе темы; скрытая панель браузера проверяется с отключёнными переходами;
   - числа в отчёте: «сдвиг 235 px», «слайдер 120 → 239 px», «на 4 px выше из-за `.table`».
6. **Каждое решение — три следа:**
   - строка реестра (изменение, почему, доказательство, будущий владелец, откат);
   - проверка гейта по готовой странице (сейчас в гейте 489 проверок);
   - запись журнала в конце этапа (решения и отвергнутое, без хроники).
7. **Откат без самолюбия.** Если изменение читается как баг, прежнее поведение возвращают, а удачную часть оставляют (MAP-P36 → P37).
8. **Непонятное объясняется на данных.** «Что значит пункт 7?» — ответ на реальных целях с реальными счётами, и только потом реализация.

## 13. Чек-лист для следующих страниц

### Смысл

- [ ] У каждой части сформулирован вопрос, и он виден первым.
- [ ] Один сигнал — одно место; дубли убраны.
- [ ] Цвет судит только там, где страница судит; статус и иерархия — разные каналы.
- [ ] «Нет данных» объясняет почему; ложного зелёного нет.

### Раскладка

- [ ] Каждый клик (вид, слой, фильтр, панель, тема) оставляет все блоки на месте на 1280, 820 и 375 px.
- [ ] Место резервируется, а не появляется; длинное уходит в «+N», а не во вторую строку.
- [ ] Анимация идёт к точным размерам, раскрытие и складывание — с одной скоростью.

### Управление

- [ ] Выбранное нейтрально, без акцента сайта; подсказки — одно простое предложение за «?».
- [ ] Прогрессивное раскрытие: обзор → сигнал → детали → улики; особое (Overall) раскрыто сразу.
- [ ] Пустое не прячется, а бледнеет и объясняет; ненужное прячется, недоступное выключается.
- [ ] У каждого действия мышью есть клавиша; роли ARIA, одна остановка Tab на группу.

### Движение

- [ ] Движение только для исключений и переходов; есть reduced motion.

### Система

- [ ] Общий runtime; страница — описание; различия только смысловые.
- [ ] Классы в своём пространстве имён; проверено, что компонент не красят ни тема (`.table`), ни соседний компонент (`tf-map-view`).

### Процесс

- [ ] Варианты на демо-страницах, референсы с конкретным приёмом.
- [ ] Каждое решение — строка реестра, проверка гейта, браузерная проба; в конце этапа — запись журнала.
