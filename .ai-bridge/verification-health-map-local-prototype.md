## Rules for this prototype

- Prefer changes that are reversible in minutes.
- Do not propagate to DocOps, py-testkit, template-components, or other consumers until the UX is accepted.
- Every local shortcut must be listed below with its intended owner if accepted and cleanup action if rejected.
- Keep Verification Health Map semantics derived from the existing authoritative Sphinx-Needs graph; no second source of truth.

## Observations / pending decisions

- Current role of this page: **operational test-health monitor**, not semantic “verified/proof” status. Goal/Capability/Requirement/TREQ define the spatial scope; raw retained test execution defines the health shown inside that scope.

- Current color contract: **green = all declared linked tests passed**; **red = at least one failed test**; **amber = broken/error, skipped, unknown, or a required test kind has no retained result**; **gray = no linked tests**.

- Current hover is the ordinary Plotly tooltip next to the cursor, on a navy #0f2537 surface with cyan #38bdf8 border/accent and white text. It shows aggregate passed/total plus separate BDD / Integration / Unit / Property counts; on unhealthy nodes it names the first concrete failed/missing item.

- Test-health aggregation rolls upward: a failing/missing Requirement/TREQ makes its containing Requirement/Capability/Goal unhealthy and the parent hover reports the same hole in branch totals.

- **JUnit is the authoritative retained execution input used by the portal health projection; Allure is the forensic browser for the same run.** The map therefore uses the graph to scope tests and the retained execution result to color them, then drills into Allure for raw analysis.

- Allure 3 direct test-case links were verified. The report hash is md5(uuid) from the raw Allure result. All 117 test-evidence nodeids in the current retained run map one-to-one to 117 Allure report ids, including pytest and pytest-bdd parameterized cases.

- Drill-down policy under MAP-P11: **every real square opens Allure filtered to exactly that square’s declared test set**, independent of how many source modules are involved. All 68/68 scope-tag result sets were machine-checked for exact ID equality against the map aggregation; representative Goal/Capability/TREQ links were also checked in Chrome.

- Current real retained run is 117/117 passed: BDD 58, Unit 34, Integration 22, Property 3. Failure and missing-result propagation were tested by temporary mutation of generated needs.json and the file was restored afterward.

- Current trial label policy remains **all 9 Goals + all 15 Capabilities always visible** at the normal portal viewport; Requirement/TREQ are unlabeled treemap cells inspected by hover/click.

- Area semantics under MAP-P10: every Requirement/TREQ contract contributes one unit; Goal/Capability area shows the number of declared contracts below it. Area is not priority, risk, effort, or test count.

- Correct browser workflow remains normal Chrome Profile 1 through agent-browser; no alternate browser/headless profile is used.

- Allure default expansion under MAP-P12 was verified from clean browser storage: the Provider portability scoped view rendered 15/15 visible tree sections opened; the full 117-test report rendered 51/51 sections opened. This uses Allure's own expandedTrees/collapsedTrees state, not post-render click automation.

- MAP-P13 dashboard currently reads **117/117 retained results passed**, **68/68 scopes healthy**, **44 declared contracts**, **0 required-result gaps**, with BDD 58/58, Integration 22/22, Unit 34/34, Property 3/3.

- Retained-run provenance is intentionally shown from Allure itself rather than the current checkout. Current retained run reports branch fix/adopt-template-1.25.2, run c9b92989…, start time, age, 13.4s duration, and Allure 3.16.0.
