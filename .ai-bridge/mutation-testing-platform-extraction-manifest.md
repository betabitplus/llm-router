# Mutation testing platform extraction manifest — llm-router P34

> Status: **active llm-router pilot migration ledger**. This document records what has been proven locally and where reusable pieces may belong **after the pilot is explicitly finished**. It does **not** authorize current platform work or rollout to any consumer.

## PILOT SCOPE GUARD — authoritative operating rule

**Until the user explicitly declares the llm-router pilot finished, all feature development happens inside `llm-router`.** Future platform owners listed in this document are a migration ledger only; they are not authorization to implement or propagate anything in those repositories.

The only allowed platform intervention during the pilot is the minimum change required to unblock a concrete llm-router experiment that cannot be performed locally. Any such exception must be recorded here with the blocker, exact intervention, why a local workaround was insufficient, future clean owner, and cleanup trigger. Otherwise: do not edit platform repositories, do not update consumer pins, do not release, do not roll out to other consumers.

Local prototype code may be deliberately ugly or repository-specific while we learn, but every temporary choice must record its likely future owner and replacement trigger here. Cleanup/migration happens only after the feature is useful and accepted live in llm-router.

No mutation percentage gates any contract.

Across the current contracts: 214 caught (3 by the time limit) · 17 survived · 38 not reached · 8 invalid · 32 arid or pardoned.
- The pull-request diff (`--refresh-implementation-faults --diff main`) mutates only changed, attributable and covered lines and writes `test-results/implementation-faults/diff/`: 2 findings on 262 changed source lines, as GitHub annotations.

The Test Plan's Generation budget defers calls, never passes them.

- `REQ_INVALID_CONFIGURATION_ERRORS` owns its public System semantic coverage **1/1 PASS · 1/1 path**; its Implementation classes come from the campaign, its specification, architecture, interface and runtime classes from the specialized probes (`docs/_build/html/assurance-fault-model-facts.json`).

- Platform extraction remains frozen. The implementation is local to `llm-router`; future ownership below is a ledger only.

## Non-negotiable extraction rules

01. **llm-router remains the only mutation-testing pilot consumer until the user accepts this pilot and platform parity is proven.** No other consumer gets these changes early.
02. Sphinx-Needs remains the authoritative engineering graph. Platform extraction must consume graph relationships; it must not introduce a second requirements source of truth.
03. A fault class is caught only when every valid, unsuppressed mutant of that class in the contract's attributable code fails one of the contract's passing tests. There is no mutation score; a survivor on a changed line is the signal.
04. Shared implementation ownership stays **N/A** until attribution is objectively resolvable; never allocate a shared line heuristically.
05. Noise is removed before anything runs and stays visible: arid-code rules from the Test Plan (a profile may turn one off with a reason), a static validity filter, and the `# mutation:` pragma with a category and a reason. A suppressed mutant never counts as caught; a pragma that covers no mutant fails the build.
06. Mutation Testing Elements stays the forensic UI of the standard Mutation Testing Report Schema report; Ternforge pages judge, count and route, they do not rebuild MTE.
07. A semantic mutant counts only after the qualified deterministic cascade; without a distinguishing input it is UNKNOWN, never green, and a draft test is kept only through the cascade's filters.
08. Every model call goes through the metered adapter: no tools, a JSON schema validated again on receipt, one ledger row per call, deferral above the budget that never passes. A generated mutant or draft is exactly a stored, ledgered answer, model code is confined to what its module can already do, and a selected target without a mutant keeps its class UNKNOWN.
09. A survivor is decided only by an input that execution confirms, from the symbolic search or an assessor; an assessors' equivalent is advisory, a label above a split-conformal threshold replayed from frozen calibration answers, never an outcome, and the triage of rule survivors never changes one.
10. A verdict model decides every survivor and every unreached mutant inside a requirement's scope (pin, equivalent or irrelevant, with its reason); a suppression counts only when a review model of another family agrees, and a disagreement pins the mutant; only a decision about what a Feature or Goal promises escalates to the person, whose verdict wins; a pin is adopted only after the cascade keeps it in the project's style (lint-clean, five passes on the original, failing on the mutant) and counts for no coverage case and no depth, and every model answers for its role only after passing that role's canaries (ADR_0006).
11. The operators rank by the recorded verdicts' productivity for the pull request's one finding per line, a survivor with a recorded suppression is no finding, and the assessors are calibrated on real survivors the symbolic search left unsure and a pin proves distinct as well as on labelled pairs (ADR_0003, ADR_0005).

## Premature platform spike cleanup — learnings retained, implementation discarded

A short-lived attempt was made to start future extraction before the llm-router pilot was finished. That was outside the intended operating model. The platform-side branches were deleted and all four touched owner repositories were verified back on clean `main`. **Nothing below is an implemented platform feature.** These are only findings that must not be lost when clean extraction eventually begins.

### Candidate `py-testkit` ownership — later, not now

- Generic future responsibility: mutation executor boundary, stable mutant fingerprinting, standard Mutation Testing Report Schema 2.0 production, linked-test-only attribution, and direct execution timing.
- Historical (mutmut retired by ADR_0003): adding mutmut directly to the normal testkit dependency graph conflicts with the existing DocOps/click range. The active llm-router pilot therefore keeps mutmut out of normal dependencies; when the engine is absent, `.ai-bridge/build-mutation-report-prototype.py` relaunches itself in an isolated `uv run --with mutmut==3.8.0` overlay while preserving the project environment.
- Historical (mutmut retired by ADR_0003): mutmut 3.8 reads its config during import, so the runner prepares temporary config before importing engine internals and restores repository state in a parent-owned `finally`.
- Historical spike proof worth retaining: the extracted prototype reproduced the then-current three llm-router scores exactly (61/41 = 59.8%, 51/49 = 51.0%, 28/3 = 90.3%) while keeping report tests/`coveredBy` inside declared linked tests. The Invalid Configuration contract has since expanded to a 16-test mutation-linked scope and now measures 84/26 = 76.4%; future extraction must reproduce the current denominator rather than treating the historical spike score as canonical.
- **Current status:** no py-testkit mutation implementation is retained; the premature local branch is deleted. The llm-router-local runner now owns isolated engine bootstrap plus full/diff execution for the remainder of the pilot.

### Candidate `ternforge-infra-ci` ownership — later, not now

- Generic future responsibility: full/diff orchestration, previous-state retrieval, retained run/baseline history, immutable run provenance, cache/artifact lifecycle.
- Spike finding: reuse and audit evidence have different roles — cache is suitable for previous-state reuse, while a normal artifact is suitable for retained downloadable evidence. Any future extension should be default-off and stay inside the existing required CI lifecycle rather than creating a second mutation-specific workflow.
- Real llm-router retained state already demonstrates a baseline chain crossing full and diff campaigns without self-baselines.
- **Current status:** no infra-ci mutation extension is retained; the premature local branch is deleted. During the pilot, llm-router keeps the campaign and run snapshots under `test-results/`.

### Candidate `py-policy` ownership — later, not now

- Generic future responsibility: structural validation only, not scoring or graph ownership inference.
- Critical boundary: Sphinx-Needs remains the authoritative ownership graph. Future policy should consume graph-derived facts rather than parse `@impl` independently or create a second mapping.
- Invariants learned: only uniquely attributable scopes may carry a requirement-level score; shared implementation scopes stay N/A; suppression requires contract + mutant fingerprint + non-empty reason, with optional nonblank owner and valid nonexpired expiry; suppressions affect actionability, never raw score.
- Spike proof worth retaining: llm-router's three unique measured facts plus the two shared ownership pairs validated cleanly; deliberately attributing the shared route scope produced the expected shared/N/A rejection.
- **Current status:** no py-policy mutation implementation is retained; the premature local branch is deleted. Local llm-router prototype remains authoritative for the pilot.

### Candidate `ternforge-tooling-docops` ownership — later, not now

- Generic future mutation responsibility: class judgement by outcome, the explorer and monitors, the MTE report page and its versioned static dependency. **Contract Evidence is separate traceability/assurance UX and must not be used as a mutation detail page.**
- Broader DocOps lesson from P28/P29/P30/P31/P33: Living Specifications own semantics/proof logic/code binding and may link outward to raw execution/assurance, but must not embed current pass/fail, verification-depth boundary mechanics, evidence-producer inventories or assurance gaps. Contract Evidence owns explicit Assurance Targets, one Guarantee Frontier, path qualifiers, Target−Actual gaps, fault-model coverage, trust argument and retained history; Health/Depth own monitoring. P33 adds an extraction requirement on presentation: the default Contract Evidence path must remain scan-first/progressive-disclosure rather than exposing every assurance diagnostic as a peer block.
- Spike finding: DocOps already has the right transient generated-source lifecycle and package static path, so later clean extraction should generate pages before Sphinx rather than patch built HTML.
- Spike finding: the accepted forensic UI should remain upstream Mutation Testing Elements; Ternforge should add only navigation/provenance around `<mutation-test-report-app>`, not rebuild MTE controls.
- Important blocker discovered for later clean design: current llm-router Sphinx-Needs IMPL nodes export `source_url` line anchors but not Python callable/scope identity. The two shared-scope cases therefore **must not** be inferred merely because source markers are adjacent. A future clean solution should export objective source-scope identity from the Python source-tracing layer where AST context is known.
- **Current status:** no DocOps mutation implementation is retained; the copied MTE asset / premature E4 branch is deleted. The llm-router generated portal remains the only active implementation.
